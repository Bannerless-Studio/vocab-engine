# Pack schema

A pack is one directory of JSON files that holds all the language-specific data. The engine reads nothing else.

```
<packdir>/
  pack.json        required  metadata and rules
  words.json       required  vocabulary
  sentences.json   required  example sentences (may be [])
  lessons.json     optional  "Sounds" tab lessons; required when pack.hasLessons is true
  passages.json    optional  "Read" tab graded passages with questions
  characters.json  optional  character-stage units; required when pack.characters is set
  script.json      optional  script-primer units; required when pack.script is set
  legacy.json      optional  old-app id maps for one-time progress migration
  pack.js words.js sentences.js lessons.js characters.js script.js legacy.js   generated, never edit by hand
```

The `.js` files are generated with `python3 tools/jsonify_pack.py <packdir>`. They hold the same data as `const PACK=`, `WORDS=`, `SENTENCES=`, `LESSONS=`, `CHARACTERS=`, `SCRIPT=` and `LEGACY=`, so the app can load them from `file://` and `build.sh` can inline them. `passages.json` has no file of its own: its `const PASSAGES=` is appended to `sentences.js`, so `build.sh` and the dev loader need nothing new, and a pack without passages gets exactly the `sentences.js` it had before. `characters.json`, `script.json` and `legacy.json` follow `lessons.json`'s pattern instead: their own optional generated file, present only when the source `.json` is. `tools/validate_pack.py` fails when they are stale.

| `name` | string | yes | Display name and page title, e.g. `"Mandarin (HSK 1–4)"`. |

| `ttsRate` | number 0.1–3 | no (0.9) | Speech rate. |
| `audio` | `{voice, version}` | no | The pack ships recorded clips (docs/AUDIO.md, written by `packbuilder audio`). `voice` is a non-empty string, `version` an integer ≥ 1 that names the service worker's audio cache, so a new version never plays a stale cached clip. With it, the no-voice notices are not shown. Clips play with or without it. |
| `levels` | `[{id, label}]` | yes | Ordered levels. `id` is a string (`"1"`, `"A1"`), `label` is shown in the UI. The order drives set unlocking and "past this level" logic. |
| `setSize` | positive int | no (10) | Words per learn set. |
| `placement` | `[[levelId, bucketCount], …]` | yes | Placement-test buckets, in level order. Each level's sets are split into `bucketCount` contiguous buckets. Buckets cycle through `placementItems` test items each (default 2 then 3, so 16 buckets give a 40-item test). Every bucket needs at least 3 words. Levels before the first listed level count as known once the first bucket passes. |
| `placementItems` | `[positiveInt]` | no (`[2, 3]`) | Item counts cycled per placement bucket (core.js `placementItemCount`); the default alternates 2 and 3, today's fixed pattern. |
| `functionWords` | `[wordId]` | no | Word ids never blanked in cloze (gap) items: articles, pronouns, particles. They are also a word class for options: a content-word answer in recall or cloze never gets a function-word distractor, and a function-word answer gets other function words first (with `optsMix`, first within each side). |
| `clitics` | `[string]` | no (none) | Possessive/emphatic suffixes attached directly to a word with no separator (Indonesian `-nya`, `-lah`, `-kah`, `-ku`, `-mu`; listed without the leading hyphen, e.g. `"nya"`). Extending a cloze blank past a hyphen-joined repeat of the matched form on either side (`anak-anak`, धीरे-धीरे) runs for every pack, unconditionally; `clitics` adds only the further extension past a matching suffix (`alat-alatnya`), and rejects a fused hit that would spell a different real pack word instead (`ada`+`-lah` = `adalah`) (core.js `locateWord`/`extendRedupClitic`). |

Its value lists the citation articles of the words it agrees with (`"den": ["der"]`). Distractors cited with an agreeing article are offered first, so the visible article never gives the answer away. Defaults exist for fr, es, it and de (core.js `ARTICLE_AGREEMENT`), picked by `langTag` or the `tts` language. A key missing from the table agrees only with itself. |
| `typing` | object, `"pron"` or `null` | no (`null`, validator warns when absent) | `null` turns off typed production. Recall items are used instead, so review still keeps at least 40% production. Object fields are listed below. `"pron"` alternates a typed-reading item (tones optional, no audio) with a typed-characters item (audio played; silent before the answer under `typedFrom`); see "Pronunciation aids" below. Either form of typed production also accepts, alongside `w` and `alt`, a word's affix-bare and slash-/parenthetical-alternative forms (core.js `affixAlts`): a leading/trailing `〜`/`～` or ASCII `-` is optional to type (年 for 〜年, 이다 for -이다); a bare form with a `/` (Korean -이/가) also accepts the slash form without the affix (이/가) and each alternative alone (이, 가); a bare form with a single `(x)` optional-syllable group (Korean -(으)로, -(이)나, -(이)랑) also accepts the form with the group's parens dropped (으로) and the form with the whole group dropped (로). An inner hyphen or tilde (Hindi `धीरे-धीरे`, 年〜年) is never treated as an affix mark. A word's `forms` (inflected surfaces, see the words table) are never accepted: "Type the word" wants the word itself, so 食べない is wrong for 食べる while 食べる, たべる (an `alt`) are right. Only a cloze item accepts the literal inflected surface its blank covers. |
| `typing.caseSensitive` | bool | no (false) | When false, both sides are lowercased before comparing. |
| `typing.accents` | `"lenient"` or `"strict"` | no (`"lenient"`) | With lenient, optional marks are folded on both sides: Latin accents (`perche` = `perché`), stress marks (`молоко́`), Arabic-script harakat and tatweel, Hebrew points, and ZWNJ/ZWJ (`میروم` = `می‌روم`). Lenient also folds optional spelling variants in Arabic script and Devanagari (hamza carriers, ء, ة, ى, ھ, nukta, chandrabindu; see "Lenient typing letter folds" below), and, for the German pack only (`key === "de"`), German ASCII substitutions: each target word is additionally compared against ä → ae, ö → oe, ü → ue, ß → ss folded onto it, so `Muede`/`Strasse` are accepted for `müde`/`Straße` alongside the plain accent-stripped `mude` every other Latin-script pack already accepts (core.js `GERMAN_ASCII`, `foldGermanAscii`; see "German ASCII substitutions" below). The digraph fold only ever runs on the target, never on what was typed, so a real "ae"/"oe" in the typed text (`Aerobic`) is never mistaken for ä/ö. Every lenient fold is guarded: an answer that matches only after folding is wrong when it is exactly another pack word (`si` for `sí`). Marks that make a different letter are kept: Cyrillic й and ї, Devanagari vowel signs, and kana voicing marks. Strict never folds them. Arabic kaf and yeh always equal their Persian/Urdu forms (ک, ی), in both modes, because keyboards produce either. |
| `typing.strictFromLevel` | levelId or `null` | no | With lenient accents, folding stops at this level and every later one. `null` means lenient at every level. |

Needs `typing`; without it the field does nothing. Off by default; only zh sets it for now. See "typedFrom and glossFocus" below. |

| `legacy` | `{key, format}` | no | Marks this pack as the successor to an old standalone app's saved progress, for a one-time migration. `key` is the old app's localStorage key (e.g. `"hsk_pinyin"`); `format` is a migration-function tag (e.g. `"hsk-v2"`). Requires `legacy.json`. |

### Lenient typing letter folds

With `typing.accents: "lenient"` (at levels before `strictFromLevel`), typed answers also fold these optional spelling variants, on both sides (core.js `LENIENT_LETTERS`, `foldLenientLetters`). Strict typing folds none of them.

| script | folds |
|---|---|
| Arabic script (ar, fa, ur) | Hamza/madda on a carrier dropped: أ إ آ → ا, ؤ → و, ئ → ی, ۓ → ے, ۂ → ہ, ۀ → ه, and a loose hamza mark (خانهٔ → خانه). ٱ ٲ ٳ ٵ → ا, ٶ ٷ → و, ٸ → ی. Standalone ء dropped. ة → ه, ۃ → ہ. ى → ی. ھ → ہ (بھائی = بہائی). |
| Devanagari (hi) | Nukta dropped (ज़ = ज, including precomposed क़–य़ U+0958–095F). Chandrabindu ँ → anusvara ं (माँ = मां). |

Not folded: a leading ال (it changes the word; `كتاب` ≠ `الكتاب` when typing), and ه vs ہ (each pack spells with one).

### German ASCII substitutions

With `typing.accents: "lenient"` and `key === "de"` (at levels before `strictFromLevel`), each target word (`w`, `alt`, and any `extra` surface) is folded a second way, on top of the plain Latin accent strip every Latin-script pack already gets: ä → ae, ö → oe, ü → ue and ß → ss (core.js `GERMAN_ASCII`, `foldGermanAscii`), gated to the German pack so no other pack's text is affected. A typed answer is accepted if it matches either folded form of any target, so a learner who drops the umlaut entirely (`mude` for `müde`, exactly as every other Latin-script pack already accepted) and one who types the digraph a German keyboard-swap convention actually uses (`Muede`, `Strasse`) are both right, and typing ä/ö/ü/ß directly still works. The digraph fold only ever runs on the target, never on the typed text itself: a real "ae"/"oe" digraph a learner actually typed (`Aerobic`) is compared as ASCII text throughout and is never turned into ä/ö by this pass, so it is never mistaken for a German word spelled with an umlaut. Because the digraph fold is additive rather than a replacement, it does not remove any collision the plain accent strip already created: `schon`/`schön` and `zahlen`/`zählen` (see the collision table below) still fold to the same key and are still caught by the same guard. An audit of `german/pack/words.json`'s `w` and `alt` fields found no *additional* pair that collides only under the digraph half of this fold (e.g. an ASCII `ss` word folding into a `ß` word the way `schon`/`schön` already collide via the plain strip); the collision guard below still covers that class generically if one is added later (proven with a synthetic `Masse`/`Maße` pair in `tests/engine_checks.js`).

**Collision guard (every lenient fold).** Folding can make distinct words one typed key: Spanish `si`/`sí`, Arabic ما "what"/ماء "water". core.js `acceptTyped` first compares strict forms (no accent or letter folding; case, whitespace, apostrophes and kaf/yeh unified as always). An exact match to the target always passes. Otherwise, in lenient mode, an answer that matches only after folding (Latin/Greek/Cyrillic accents and stress, Arabic marks, joiners, the letter folds above) is rejected when it spells another pack entry's `w` or `alt`: its strict form is that entry's, or its form without non-distinguishing marks (Arabic harakat and tatweel, Hebrew niqqud, ZWJ/ZWNJ, Cyrillic stress; core.js `pointingKey`) is that entry's and not the target's. So `مَا` or `مـا` typed for `ماء` is wrong, and so is `si` with a joiner typed for `sí`. Stress-less `замок` stays right for `за́мок` even when `замо́к` is also a pack word, because the target shares that form; typed `замо́к` is wrong. The guard needs the pack word list (`acceptTyped`'s `words` argument; the app passes `WORDS`); without it the fold alone decides. So `si` is wrong for `sí` and `ماء` for `ما`, while `perche` for `perché`, `еж` for `ёж` and `امس` for `أمس` are right. Strict mode is unchanged.

### Script display

Every element that shows target-language text carries `lang` (from `langTag`) and, when `rtl` is true, `dir="rtl"`. It also uses `fontFamily` and `lineHeight` when they are set. These elements are headwords, sentence text, word options in recall and cloze items, the cloze sentence with its blank, the typed-answer input, Words-list and teach-card rows, example sentences, reveal blocks, and lesson `rows` word cells and `say` buttons. English glosses, translations and `pron` never carry them, so they stay left-to-right; see "RTL rendering" below.

- Block elements align to their start side, which is the right in RTL. The big headword stays centred.
- Inline target text inside a mixed line, such as an option button with its number and `pron`, is wrapped in `<bdi>`, so the line never reorders. Word option buttons in RTL packs also run right-to-left, with the number on the right.
- The cloze blank `____` is bidi-isolated, so it sits where the missing word was in RTL text too.
- The Words search box uses `dir="auto"`.

#### RTL rendering

For `rtl` packs, target-language text and UI/English text never share a bidi context. Mixing them lets the bidi algorithm reorder the Latin run: `79 words` shows as `words 79`, and a gloss such as `near; (someone) has (میرے پاس: I have)` scrambles. The rules, all in engine/app.html, change nothing for LTR packs:

- **Target text** is an element with `data-tl lang dir="rtl"`: `TA`, or `tw()` for an inline `<bdi>`.
- **UI/English lines inside a target-language block** carry `dir="ltr" data-ui` (`UIA`). This includes digit-only lines. Examples are the Read-list meta line and the done tick `✓ 3 / 4` inside the RTL title button, option numbers, the `pron` beside a word option, and the weak-word reason labels. They get their own isolated LTR context and the UI font.
- **The gloss popover** (`#gloss` and the sentence token popover) is an LTR line, right-aligned in RTL packs. The word is an isolated `dir="rtl"` span, and `pron` and gloss follow as LTR runs, so a wrapping gloss never interleaves with the word. The results' weak-word rows are RTL flex rows with the checkbox on the right, where each piece is its own flex item.
- **Any UI/English string that can embed target-language text** goes through one renderer, `ui()`. That covers glosses, sentence translations, notes, lesson text, labels and the Today plan lines. It escapes the string and wraps each run of RTL script (core.js `rtlRuns`) in `<bdi data-tl lang dir="rtl" class="tlf">`, so `(bound: لـ)` keeps its order and the fragment gets the pack font. A run extends across neutrals (`...`, `…`, `/`, commas, digits, spaces) up to the last RTL letter before a Latin letter, as the Unicode bidi algorithm resolves them. So `از ... متنفرم` and `کا/کی/کے` stay one run in their own order, while `: I have)` after `میرے پاس` stays outside.
- **A pack label inside a UI line**, such as a stage label or a symbol's name, uses `tf()`. That is `ui()` for RTL packs, so a Latin name such as `choṭī he` stays UI text.
- **Inline fragments** (`.tlf`) have their line-height capped at 1, so a tall script such as Nastaliq at `lineHeight` 2.6 does not grow the UI row it sits in.

Tests check these rules on rendered markup with tests/fixtures/rtl_audit.js `rtlAudit`, from script_app_checks.js [14], engine_checks.js "RTL rendering rules on the Read screens" and characters_app_checks.js [rtl]. No UI text node, meaning Latin letters or digits without RTL letters, may have `dir="rtl"` as its nearest `dir`. RTL-script text must be inside `data-tl`, and Latin text inside `data-tl` needs a `data-ui` element in between.

**External resources.** The only external resource a built page may load is Google Fonts. The page always loads IBM Plex Sans, and it loads `pack.fonts` at runtime through a `fonts.googleapis.com/css2` URL built by core.js `fontsHref`. No other URL can come from a pack. Neither font stylesheet blocks first paint: IBM Plex is a `preload` that becomes a stylesheet once loaded, and the `pack.fonts` link starts as `media="print"` and switches to `all` on load. Text shows in the fallback stack until the webfont arrives (`display=swap`).

**Pronunciation.** `pron` is display-only. With "Show pronunciation" on (the default comes from `showPron`), a word's `pron` is shown under the headword, beside it in word options, Words-list rows and teach-card rows, and under the word in every reveal. A sentence's `pron`, such as a kana line or romanised Russian with stress marks, is shown under the sentence in read items, example sentences and reveals. It is never shown before a hear or cloze item is answered, because it would give the answer away.

**Example-sentence highlighting.** In teach cards and reveals, the taught word is bolded in each example sentence wherever it is visible. The word is found the same way as for cloze: `w`, every `alt` and every `forms` entry (core.js `textForms`), whole-word when `spaced`, overlapping hits merged into the widest one. A hit inside a longer pack word or compound is not bolded, so 本 inside 日本 is left plain. So a ja sentence with 食べた bolds it for 食べる through `forms`. When the word is not visible, as when it appears only inflected and no `alt` or `forms` entry matches, nothing is bolded. This is core.js `highlightParts`.

**Words search** matches the query against `w`, every `alt`, every `forms` entry (食べた finds 食べる), `pron` and the gloss. Both sides are lowercased and accent-folded as in lenient typing. Whitespace is also ignored, so `nihao` finds `nǐ hǎo`. A hyphen folds to a space, so a reduplicated or hyphenated lemma (`धीरे-धीरे`) matches its unhyphenated spelling (`धीरे धीरे`) too. A romanised nasal tilde (`kahā̃`) folds to a literal `n`, so plain ASCII typing (`kahan`) finds it, alongside the existing macron/dot-below folding (`ā`, `ṛ`). This is core.js `searchWords` (`searchFold`); typed-answer checking (`normalizeTyped`/`acceptTyped`) is unaffected by any of the folds below.

Arabic-script text (ar/fa/ur) has its own search folds, separate from the lenient typing letter folds above (search keeps ھ and ء, and makes ال optional): hamza and madda on a carrier drop (`انا` finds `أنا`, `سوال` finds `سؤال`), ٱ is ا, ة/ه/ۃ/ۀ all fold to ہ, ى is ی/ي (`فى` finds `في`), and a leading ال is optional on both sides (`كتاب` finds `الكتاب`). Urdu spelling variants of the same letter are unified to Urdu heh goal ہ — Arabic heh ه, teh marbuta goal ۃ, and the Arabic-preset ۀ all fold to ہ (`مدرسۃ` finds `مدرسہ`) — while do-chashmi heh ھ (a distinct aspirated phoneme) is never folded into ہ. Bari ye ے folds to ی at a word boundary only (`بڑے` and `بڑی` search as the same word); this is a deliberate tradeoff, since ے is otherwise indistinguishable from ی for search — a reveal still shows the pack's own spelling.

Devanagari text (hi) is also folded for search, the same two folds as lenient typing: nukta folds away (`जरूर` finds `ज़रूर`, `लडका` finds `लड़का`), including from a precomposed nukta letter (क़ ख़ ग़ ज़ ड़ ढ़ फ़ य़, U+0958–095F, decomposed first); chandrabindu ँ folds to anusvara ं (`हैँ` finds `हैं`), a common informal spelling swap. ZWJ/ZWNJ are dropped for every script.

### bareBy

`"bareBy": "typed"` (zh only; owner feedback 2026-10-02: "writing practice should score more than selection practice", "it feels it takes more than 3/6 attempts for mastery"). A unit's streak (`prog.chars.c`) decides its tier: below `mastered` the word shows by its reading, from `mastered` written with ruby, from `bare` written alone. Without the flag every right unit answer (all four choice kinds) adds 1 and any miss resets to 0, and typed word answers never touch the unit.

- **Credit** (core.js `markUnitTyped`, app.html `markUnitTyped`): a right typed answer of a written-side kind on the unit's word (`written`, `writtenMeaning`, `writtenPron`; the unit is the one whose `words[0]` is the word) adds 1 to the unit, a typed miss is a unit miss (floor below). A synonym's characters accepted for meaning -> characters (`typedSyn`) are right for the word record and its `w:` day-log entry but move no unit (neither word's), log no `c:` answer and show no dots: the learner did not write this word's characters (review 2026-10-02). Only a recorded (taught) unit moves; no record is created. The in-drill retry after a miss and the second-miss choice fallback give the unit nothing. Reading kinds (`pron`, `pronMeaning`) never touch the unit.
- **Hold** (core.js `markChar(prog, id, ok, pack, held)`): from `mastered`, a right choice answer (charRead, charSound, charPick, charRecall) counts in `r` but leaves the streak; only typed credit takes the unit from `mastered` to `bare`.
- **Miss floor**: from `mastered`, any miss (typed or choice) drops the streak to `mastered`, so the characters stay shown. Below `mastered` a miss resets to 0 as before.
- **Exemption** (core.js `typedUnitWords`): a unit whose word takes no written-side kind of the pack's rotation (`typedKindOk` rejects each: shared spelling, no gloss, `noTypedMeaning`) is not held: choice answers take it to `bare` as before. On zh no unit is exempt, since meaning -> characters (`written`) needs only a written form.
- **Scheduling** (core.js `dayPlanKinds`, `typedUnitDue`; needs `dayAware`): a held unit between `mastered` and `bare` is a dayAware candidate with kinds `["type"]` and alias `w:<word id>`; when picked (the consolidating share, `DAY_TYPED_CONSOLIDATE_SHARE` 0.25 under this flag, 0.15 otherwise: ⌈0.25 n⌉ = 5 in Review, 2 in Recall, plus misses first), it is planned as `{ kind: "type", word, tu: unit id }` and the app picks a written-side kind of the rotation for it (`typedFromSlotItem` restricted to `TYPED_WRITTEN_KINDS`). The unit and its word are one item: `dayPick` never takes both, and a word taken first becomes the unit's typed item, except a word with a pending miss typing cannot settle: it is never converted, and gets its own item even when its unit was taken first, while a slot is left (since fb10 a typed answer settles any miss, so none is held back). Only the unit's own `c:` entry (a written-side typed answer) keeps it from repeating within `DAY_RECENT_SESSIONS`; the word's `w:` "type" (also logged for typed pinyin) does not. A typed answer settles any pending miss of the unit (core.js `daySettlesAt`). Under a `c:` key, kind `"type"` means typed from the written side only: it is logged by the app's `markUnitTyped` alone, never for a typed reading (pron, pronMeaning), so a typed reading cannot settle a unit's charRecall miss. A floored unit (missed at `mastered`+) never drops to the weak tier: its pending miss puts it first (tier 0, settled by its typed item); after the miss ages out (`DAY_MISS_MAX_SESSIONS`) it comes first in the consolidating share (core.js `dayAgedOut`; the day log keeps `ag: 1` on its `c:` entry over midnight until a right answer), asked typed in the next session (tests/typed_mastery_checks.js [3]). Test Characters stays choice items. Measured by tests/day_sim_checks.js [typed week] (7 days; the check: typed only reaches bare at least as often as choice credit on the same seed): 150 words / 60 units, 1 a day 15/25 (choice 8/25), 3 a day 20/25 (16/25); 595 / 300, 1 a day 16/120 (10/120), 3 a day 41/120 (29/120) (fb10-weak-floor; fb49c1b: 16/25, 18/25, 13/120, 40/120).
- **Visible streak**: the reveal of an answer that can move the unit shows its streak as dots after the answer is marked (`字 ●●●●○○`, `aria-label` "字 4/6"; app.html `unitCue`): a first-attempt written-side typed answer, and a unit choice item unless the unit is held (at `mastered`+). Pinyin typed answers, word choice items and retries show none.
- **Storage**: no new key; one optional day-log field. Unit records keep `{r, w, s}` and their meaning; the day log gains entries `c:<id>` in kind `"type"`, a value `w:` entries already carry (an engine without the flag reads them as an unrelated kind), and `ag: 1` on a `c:` entry whose miss aged out (an engine without it drops the mark at its next midnight carry). Stored units at 3–5 wait for typed answers; units already at 6+ stay bare (tests/migration_checks.js [write]).

### withWords

`"withWords": true` (zh until fb3-lag replaced it with `learn: "lag"`, see "learn" below; review 2026-10-02: the blocking choice card put a mid-HSK 2 learner on 15 character sets in a row, and Skip deferred every character to after HSK 4). No choice card. Whenever a characters stage is unlocked (its `after` level's words learned) and not finished, and words remain to learn, Today's Learn takes turns: `chars.turn` (`"c"` or `"w"`) names the kind the next Learn teaches, the oldest such stage's next set (10 units) or the next word set (core.js `nextStage`). With no word left it is character sets every session; with no stage pending, words every session. Review is the characters-started size (20) as soon as a stage is pending, whatever the turn. A set never re-teaches a recorded unit (core.js `nextCharSet`; the old single stage's sets straddled HSK 2/HSK 3).

"Later" is the stored `chars.defer` ("after" on the old card or chips): every character set after all word levels, one merged stage, as before. ### learn

`"learn": "lag"` (zh since fb3-lag; owner 2026-10-02: "Why not just a simple rule without all these settings - if character is lagging behind teach character, if not teach words?"). At each Today Learn step: if at least one full set (`setSize`, 10) of learned words has units not yet taught, Learn teaches a set of the oldest such units (pack order: level, then `characters.json` order, which on zh is word rank order); otherwise the next set of new words. With no new word left, whatever is left is taught, a last partial set included. Nothing else decides it (core.js `lagStage`, `lagUnits`, `lagCharSet`; tests/lag_checks.js). Progress shows one characters row per level (`字 HSK 1`: taught / the level's units, mastered, bare when > 0; a unit's level is its word's); display only, no stored field. The Today Learn row and the Learn card header count the set inside its lowest level, `字 HSK 3, set 18 of 30` (`lagCharSet` returns `lv`, `lvIndex` = level units taught / `setSize`, `lvTotal` = level units / `setSize`, beside the whole-pack `index` / `total`; owner 2026-10-03: "48 of 120" said nothing about where in the characters I am); display only, rebuilt from the stored `today.cu` ids, no stored field.

- **Taught** means the unit has a record in `prog.chars.c`; there is no set counter. A set is the next 10 untaught units whose word is learned (core.js `learnedWords`), so a unit is never taught before its word, never taught twice, and holes (taught units that are not a prefix of pack order) are filled oldest first. Learn reads "字, set k of n": k = records / 10 + 1, n = units / 10 rounded up.
- **What it removes** (with the flag): the per-level unlock ("字N after level N's words"), the `stages` strip segments (the strip shows word levels only), the choice card, the Progress order chips, the `withWords` turn (`charsConfig().withWords` is false under `learn`). Progress shows a separate "Characters" block (its own table, so the word rows' label column keeps its width) with one row per level labelled like the word rows, `HSK n | taught / level units taught · mastered`; when k > 0 units are bare, `HSK n | taught / level units · mastered · k bare`, with `mastered` shortened to `mast.` if the value would exceed 32 characters, the longest word-row value (a unit's level is its word's; no total row).
- **Consequences**: a fresh learner gets words set 1, its characters, words set 2, ... (characters one set behind from the second Learn). A learner far behind (HSK 1–3 learned, 250 units taught, HSK 4 not started: 345 untaught) gets characters every session for 34 sessions, until fewer than 10 are untaught (5 left), then words and characters take turns. Before (main 590af86, stored order "first"): characters for 35 sessions, then HSK 4 words only for 60 sessions, then 字4.
- **Session resume**: a Learn step planned on a characters set records its unit ids in the session record (`today.cu`); a reload or relaunch teaches the same units (core.js `lagResume`).
- **Storage**: no progress field added or changed; unit records keep `{r, w, s, …}`. Stored `chars.order`, `chars.turn`, `chars.defer` and `chars.choiceSeen` (written by the stage model) are kept untouched and never read or written under `learn`; an engine without `learn` (590af86, ea62a45, 3d66aea) boots the same record with no backup and finds its own position from the unit records (tests/migration_checks.js [lag]). A fresh record under `learn` has the flag-off `chars` keys (`v, c, defer, choiceSeen, mix`). The session record gains the optional `today.cu` (a list of unit ids; another build drops the record anyway).

### typedFrom and glossFocus

Two pack fields, both off unless the pack sets them, so every other pack plans and renders exactly as before (tests/typed_from_checks.js [5] compares against main ef44c6e; tests/flagoff_snapshot.js). zh sets both (`"typedFrom": ["written", "pron"]`, `"glossFocus": true`). A later "all languages" switch-on only needs these two fields in a pack.

**`typedFrom`** turns the production slot's typed item (see `typing: "pron"` above) into a rotation of these kinds. Plans are unchanged: the plan still says `type`; the kind is picked when the item is built.

| kind | stimulus | typed answer | needs |
|---|---|---|---|
| `pron` | meaning | reading | `pron` (typing `"pron"` only); not `pronInGloss` |
| `written` | meaning (silent; audio on the reveal) | written form | written form on display (typing `"pron"` only) |
| `word` | meaning | written form (`typeItem`) | typing object packs only |
| `writtenMeaning` | written form | one meaning | `"written"`; written form on display; no other pack word spelled the same; not `noTypedMeaning` |
| `pronMeaning` | reading | one meaning | `"pron"`; a `pron`; no other pack word with the same reading (tones included: 他/她/它 tā); not `noTypedMeaning`; not `pronInGloss` |
| `writtenPron` | written form | reading | `"written"` and typing `"pron"`; written form on display; no other pack word spelled the same |

- **Rotation** (core.js `typedKinds`, `typedSlotKind`): zh order is writtenMeaning, written, pron, writtenMeaning, written, pronMeaning, writtenMeaning, written, writtenPron. Each characters <-> meaning kind (writtenMeaning, written) comes three times per cycle of nine and each reading kind (pron, pronMeaning, writtenPron) once, so the two characters <-> meaning kinds together get twice the share of the three reading kinds (6:3) (owner feedback 2026-10-01). With `"written"` only the cycle is the same without pronMeaning; with `"pron"` only it stays pron, written, pronMeaning. The start is the slot's order among the plan's type slots plus the word's recorded answers (`r + w`). A Review has only three type slots, so slot order alone would never reach the later kinds. There is no randomness, so the same plan and progress give the same items.
- **Fallback** (core.js `typedKindOk`): a kind the word cannot take passes to the next one in the rotation. Under `pronFirst`, a word still shown by its reading never gets a kind that shows or asks for its characters (written, writtenMeaning, writtenPron), exactly as the written item already fell back. A word no kind fits gets the recall item.
- **Meaning -> characters** (`written`, app.html `silentWrittenTypeItem`): under `typedFrom` the card is silent before the answer: no audio on mount, no Replay, kind tag "characters" without "listen". Audio would say the reading, which this item is meant to practise recalling from the meaning. The reveal plays the word and shows Replay. Without `typedFrom` the item keeps its listen card ("Type the characters" under "Pronunciation aids").
- **Stimulus rules** (app.html `stimWritten`, `stimPron`): the card plays nothing before the answer and has no Replay button. Characters carry no reading, ruby or tone colours. A reading never shows its characters and has no show-written tap. Neither is a word tap. The label ("Type the meaning", "Type the pinyin"), kind tag ("meaning · any one", "pinyin · tones optional") and placeholder ("meaning…") never contain the answer. The reveal plays the word's audio and shows Replay, as other typed items do.
- **Checking**: a typed reading uses `checkPronTyped` (tones optional, "tones:" note). A typed meaning uses `checkGlossTyped`, below. Input is Latin (`lang="en"`).
- **Misses**: every kind records under `w:<id>` with miss kind `k: "type"`, as today (`applyMissedKinds`, `dropBadMissKinds` unchanged). The next review gives the word a type slot again; the rotation may pick another kind for it. From the second miss in a session the item returns as its choice counterpart: a meaning item as a silent "What does it mean?" with the same stimulus; characters → pinyin as a silent "How is it said?" with the same characters and four readings (core.js `pronChoiceOpts`: the answer plus three readings of learned words, topped up from the pack, same syllable count first, never a reading the characters also have and never two alike; picked by a hash of the word ids, no rng, and the drill shuffles the shown order with the same `Math.random` shuffle as every choice item); meaning → pinyin as recall. No new progress field, so the storage shape is unchanged.
- **Test tab**: the Test recall drill builds its items the same way, so the new kinds appear there too. Placement is unchanged.

**Typed meaning** (core.js `checkGlossTyped(val, en)`): one meaning is enough. The gloss is split into alternatives on `;` and on `,` outside brackets. The typed text is accepted when it matches one alternative, or when each of its own `;`/`,` parts does. Both sides are compared as keys (`glossKey`):

1. Unicode NFKD, combining marks removed (`cafe` = `café`), lowercased.
2. `.` and apostrophes removed without a space (`oclock` = `o'clock`, `eg` = `e.g.`); `...` and `…` vanish this way or in step 3.
3. Every other non-letter, non-digit run becomes a word break (hyphens, slashes, brackets, `!`).
4. The words `a`, `an`, `the`, `sb`, `sth`, `someone`, `somebody`, `something`, `etc` and `eg` are dropped, unless that would leave nothing.
5. A leading `to` is dropped when more words follow (`kick` = `to kick`).
6. The words are joined with no spaces, so spacing never matters.

Each `(...)` group in an alternative is optional: the alternative is keyed with every combination of its groups kept (brackets removed) or left out, up to four groups (later groups always kept). So for "to kick; to play (e.g. soccer)", `kick`, `to play`, `play soccer` and `to play (e.g. soccer)` are right and `soccer` is wrong.

Six more rules keep a typed meaning a real meaning (core.js `glossAltKeys`; tests/typed_from_checks.js [2]):

1. **Reading notes are never meanings.** An alternative or `(...)` group matching `PR_NOTE` (`also pr. [shuí]`, `(colloquial pr. [nèi])`, `colloquial pr. [xiě]`) or a bare `[...]` alternative is a note (core.js `isPronNote`). It is left out of the keys, so `also pr shui` is wrong for 谁. `glossParts` returns it in `notes`: stimuli, options and Words rows never show it (it spells a reading), and the reveal and the word popover append it dimmed, after the answer.
2. **A truncated fragment is not a meaning.** An alternative ending in `…` or `...` whose words are all function words (`to`, `be`, `is`, `are`, `of`, `and`, `or`, `that`, the dropped words of step 4 above, and a few more forms of "be") is skipped: `to` is wrong for 相信 ("…; to believe; to…"), `be` and `to be` for 只好. A truncated alternative with a content word counts (`with` for 和, `him` for 他).
3. **A lone letter left by punctuation is not a meaning.** A key of one letter counts only when the alternative is that letter as written: `i` is right for "I; me; my", `s` is wrong for 的 ("~'s").
4. **"A or B":** the text before an alternative's first top-level ` or ` also counts when exactly one word follows the ` or ` (`(...)` groups aside) and the left side has a content word (same list as rule 2): `no matter what` for "no matter what or how", `we` for "we or us…", `in confusion` for "in confusion or disorder", `hang` for "to hang or suspend (from a hook etc)". A longer right side shares its tail with the left, so nothing splits: `hot` is wrong for "hot or boiling water", `give` for "to give or have an injection", `go on official` for "to go on an official or business trip". The text after ` or ` alone never counts (`how`, `us`, `disorder` are wrong).
5. **Display of qualifiers** (glossFocus, `glossParts(en).pieces`): see below.
6. **Copula** (core.js `copulaFree`; typed-meaning packs only: `glossAltKeys(en, pack)` / `checkGlossTyped(val, en, pack)` apply it when `typedFromOn(pack)`, every other pack keeps its keys): an alternative "to be X" or "to feel X" also keys X when X is one word, an adjective or participle: `careful` for "to be careful", `anxious` for 着急 "to feel anxious", `born` for "to be born". A preposition, adverb or function word (`like`, `apart`, `away`, `over`, `left`, `able`, `there` …; `GLOSS_COPULA_NOT`) or more than one word after the copula keys nothing: "to be like", "to be apart from", "to be able to", "to be (followed by substantives only)", "to feel that ...". A learner names the quality, not the copula (owner feedback 2026-10-02).

**`glossFocus`** (core.js `glossParts(en)` → `{primary, qualifiers, notes, pieces}`; app.html `glossOut`): each top-level `(...)` group is dimmed (`<span class="dim">`) and stays inside its own alternative (the `;`/`,`-parts). A group that opens its alternative moves to the end of that alternative; any other group stays where it is. So "(of a contagious disease etc) to spread; to propagate" shows as "to spread <dim>(of a contagious disease etc)</dim>; to propagate", "just at (that time); right in (that place)" and "to be (located) at" keep their groups in place. Reading notes (rule 1 above) are removed; `glossOut(s, true)` (reveal, popover) appends them dimmed. `primary` is the text without groups or notes. A gloss that is nothing but groups, "(completed action marker)", and an unclosed "(" stay as written. It applies wherever a word gloss is rendered: drill stimuli and reveals, meaning options (hear, read, placement, charRead), character items and teach cards, Words and Progress rows, and the word popover. A passage span's own display gloss (`gloss_display.json`) is shown as written. Answer checking always compares the raw gloss.

Validation: tools/validate_pack.py does not check these two fields yet.

### Synonyms

Four optional words.json fields, generated at pack build (zh: tools/zh_gloss.js, run by tools/pack_from_hsk.py; report docs/ZH_GLOSS.md). A pack without them plans and renders as before: every rule below reads only these fields (tests/gloss_overlap_checks.js flag-off cases; tests/flagoff_snapshot.js strips them). Owner feedback 2026-10-02: 着急 "to worry; to feel anxious" and 担心 "anxious; worried" could be each other's distractor, so a right pick was marked wrong.

- **`syn`** (`[id]`, symmetric): the words share an accepted meaning. Generated: a `glossAltKeys(en, pack)` key (the key the typed-meaning matcher compares, explanatory alternatives included: 吧 "...right?" and 右边 "right" are syn) shared by both glosses, plus each pair of a reviewed group (tools/zh_gloss_overrides.json `synonyms`) for synonyms the keys miss (worry / worried), plus every `typedSyn` pair. A syn is never a wrong option for the other word (core.js `isSyn`): meaning options (`meaningOpts`: read, hear, placement, the meaning choice fallback, character `charRead` via `charReadOpts`), word options (`wordOpts`: recall in both label modes, cloze `gapChoices`) and character picks (`charOpts`: charRecall, charPick). Homonyms count ("lamp; light" and "light; easy" share `light`): a shown option "lamp; light" fits "What does 轻 mean?".
- **`typedSyn`** (`[id]`, directed, within `syn`): typing the other word on this word's meaning stimulus is right. Generated: the other word's keys (register labels such as "(coll.)" ignored, unless a label is all that tells the two glosses apart: 你 "you (informal)" / 您 "you (courteous)" stay apart, 爸爸 "(coll.) father; dad" / 父亲 "father" do not) include a key of this gloss's first alternative, the meaning a learner names first (但是 "but; however" takes 可是, 却, 不过, 然而; 词典 "dictionary" takes 字典). A first alternative that only explains ("(classifier for books)") proposes nothing. Every proposed pair is reviewed (same part of speech, same core sense, a teacher would accept it at HSK 1–3); a reject goes to the overrides' `notTyped` (`[stimulus word, typed word]`, with why: homonyms such as 晴 "clear" / 明白, 灯 / 轻 "light", 时间 / 次 "time"; near synonyms a learner must tell apart such as 再 / 又, 认识 / 知道, 喜欢 / 爱). Owner calls (2026-10-02): 会/能/可以 accept each other on the shared "can"; a borderline pair is accepted when the stimulus's first meaning is the same (讲/谈/说话 "to speak", 必须/不得不/只好 "to have to"), else re-glossed so the stimulus says which and rejected with that reason (再 "again (future, not yet done)" / 又 "again (already happened)"). **Stimulus gate** (tools/zh_gloss.js `covers`): when every alternative a word's meaning stimulus shows, its (...) groups and a leading "to" included, is an alternative of another word's gloss, the learner cannot tell the two apart, so the other word must be a typedSyn; the build fails otherwise, and the fix is a gloss that tells them apart (提高 "to raise; to improve (a level)" / 增加 "to increase; to add (in number)") or acceptance. A reviewed `synonyms` group adds typedSyn only with `"typed": true` (truly interchangeable: 着急/担心/烦恼, 突然/忽然, 一定/肯定, 可能/也许); a group without it is syn only (可能/大概, 容易/简单). The accepted and rejected lists are printed in docs/ZH_GLOSS.md. A typed item whose stimulus is the meaning accepts a typedSyn word's answer as right and the reveal names it (its first alternative only: "also right: dānxīn · anxious"; app.html `synTyped`, core.js `typedSynHit`): meaning -> reading (`pronTypeItem`), meaning -> characters (`writtenTypeItem`, `silentWrittenTypeItem`), meaning -> word (`typeItem`). The item still records the asked word. A characters stimulus (`writtenPronTypeItem`) never takes a synonym. A shared homonym is not a typedSyn: the rest of "lamp; light" tells 灯 from 轻. Typed cloze (`gapType`) is not covered: its sentence is the disambiguating stimulus, and a typing `"pron"` pack never gets it.
- **`noTypedMeaning`** (`true`): the word's core sense has no English to type: its first alternative is an explanation (bracket-only, or naming a particle, classifier, measure word, marker, prefix, suffix, "used ...", "indicating ...", or a "...right?" fragment; glosses lead with the core sense, so 本 "(classifier for books); this" is marked), adjusted by the overrides' `noTypedMeaning` add / remove (zh adds 地 "-ly" and 场). `typedKindOk` never gives the word `writtenMeaning` or `pronMeaning`; the slot passes to the next kind. The meaning choice and meaning -> word items stay. zh (26): 个 了 吗 呢 本 件 吧 张 得 正在 着 位 地 把 条 被 辆 之 分之 台 场 座 朵 棵 篇 顿.
- **`pronInGloss`** (`true`): the gloss spells the word's toneless reading (北京 "Beijing", 元 "yuan", 人民币 "Renminbi"; tools/zh_gloss.js `pronInGloss`: a run of the shown gloss words, articles aside, equals the reading's letters), so a meaning stimulus would show the pinyin answer and a pinyin stimulus the meaning. Rule: the reading and the meaning are never stimulus and answer for each other, in either direction, typed or multiple choice; allowed are characters -> meaning, meaning -> characters, audio -> meaning and characters -> reading. `typedKindOk` never gives the word `pron` (meaning -> reading) or `pronMeaning` (reading -> meaning), and the typing `"pron"` slot (`pronSlotItem`) falls back to recall. Recall (meaning -> word choice) for it is the read item while the word still shows by its reading (pronFirst); the read item (also Learn, Test, the hear fallback and placement) shows such a word by its written form alone at every tier, never its reading, not even beside the characters (`readStimHTML`), and while the word still shows by its reading the read item is a hear item when a voice can say it (served as `read`), so a pronFirst learner sees no characters; a gap item never blanks it then (the English cue spells the reading), and a sentence with no other blank is no gap item (`gapIdxs`, also the app's `daySentCan`) (owner browser check 2026-10-02: "What does it mean? / Běijīng"). Its word option sets (recall and gap once written) are labelled in the written form with no reading beside (`optScript` "written"); the app's `dayWordCan` drops recall (and a type slot no typed kind fits) for it then, so a miss is never routed to a kind the builder swaps out. Meaning -> characters stays. A gloss override that spells the reading fails the build unless it says why (`"pronInGloss": "<why>"`; zh: 元, 人民币; 角 "jiao" and 长江 "Chang Jiang" were reworded).

Gloss text is fixed at the source: tools/zh_gloss_overrides.json `en` replaces an hsk gloss (the hsk data keeps only the first two CC-CEDICT senses, so the HSK core sense was often missing or last: 给 "to; for", 才 "ability; talent", 叫 "to shout; to call"; also truncated "…", an explanation first, a list split by commas, an "or" that hides an answer) with CC-CEDICT wording, the HSK 1–4 core sense first and the answer a B1 learner types accepted (所以 "so", 检查 "to check", 饱 "full"), each with its `src` and the hsk text it replaces (`was`; a changed upstream gloss stops the build). tools/zh_gloss_expect.json lists those answers (`{word: [answers]}`, every HSK 1–3 word with a typed meaning and most HSK 4 words) and the build fails when the word's gloss rejects one. Validation (tools/validate_pack.py `check_synonyms`): `syn` and `typedSyn` are non-empty lists of other words' ids with no repeats, `syn` is symmetric, `typedSyn` is within `syn`, `noTypedMeaning` and `pronInGloss` are `true` when present. Display: an option button shows the gloss's first alternatives (up to two, about 32 letters) with a (...) explanation over 22 letters beside a meaning shortened to "(…)" (app.html `glossShort`, under `glossFocus`); the reveal shows the whole gloss.

### pronFirst

`"pronFirst": true` (zh and ja) makes a logographic pack pronunciation-first: the learner never starts from the written form. A word whose character unit is below the `mastered` tier is shown by its `pron` (pinyin, kana) wherever its written form would otherwise appear. That covers teach rows, every word drill (stimulus, options, reveal), the Words list and search, Test, Progress and result screens, and the Read tab's tap spans and popover. The unit is the one whose `words[0]` is the word. A word with no unit (a kana word) or no `pron` is shown as written. Once the unit is mastered the word is shown written, with its `pron` beside it as usual (with `characters.bareWords`, not on a drill question once the unit is bare). The written form is taught only in the characters stage (teach cards and the four unit item kinds), which is unchanged.

Sentences follow the same rule token by token (`ruby`): before characters start, or with the mix preference off, every token shows its reading. Once they have started with mix on, a token below mastered shows its reading, and the ruby and bare tiers apply from mastered. With Latin readings, tokens are spaced and full-width punctuation is shown in ASCII form. These spacing rules are display cosmetics keyed on Unicode script (Latin readings get spaces, Han text outside tokens triggers the reading-line fallback). They never affect scoring or which tier a token gets. A sentence whose written characters are not all inside `ruby` tokens (a name, a word with no unit) is shown by its sentence `pron` instead, and is never used as a cloze item. "Show pronunciation" off hides only the ruby over written tokens. The reading itself is always shown.

A small **show written** tap sits beside every word or sentence shown by its reading (never inside answer buttons or passage tap spans, which are tap targets themselves). It swaps itself for the written form, for that item only, with no progress effect, so a learner who wants the characters is never blocked. Keys pressed on it never reach the drill shortcuts. When it had keyboard focus, the revealed text takes the focus. Its label is left out of the live-region announcement.

In the characters stage, a unit's teach card shows its example sentence with that unit's own tokens written, with ruby. The other tokens follow the rule above. The example is picked by core.js `unitExampleSentences`: first a sentence with a `ruby` token of the unit's word whose tokens cover every Han character (core.js `rubyCovers`, the same test that decides the reading-line fallback), then one with the unit's token, then any other. So the card shows the unit written whenever some sentence of its word allows it.

Recall and cloze options are unambiguous when shown by their readings: no two options sound alike, and no two share a written form. Recall options are keyed by word id. A distractor with the same `pron` as the answer or another option, or written as another option's reading, is dropped. This is core.js `pronClash` in `wordOpts`.

The rules live in core.js: `displayForm(word, units, prog, pack)` returns `{text, isPron, written}`, plus `sentenceDisplay`, `sentencePieces`, `rubyTiers` and `pronFirstOn`. Validation: `pronFirst` must be a boolean.

A passage span can be longer than its linked word: 这个 links 这, 越来越 links 越, 一下 links 下. Without `ruby`, such a span reads as core.js `composeSpanReading`. Each place the word's written form occurs gets the word's `pron`. With `characters.compose`, every other character gets the reading of the single-character unit with that `t` (the first in file order). Without it, every other character stays written: a character's reading can depend on its word (ja 時 is じ in 6時, とき alone), so no reading is guessed. A character with no reading stays written, so a span never loses a character. The popover of such a span shows the tapped surface with that reading as its headword, and show written gives the surface. A span equal to its word keeps the word's own headword. A reading that starts a sentence is capitalised, including one after a sentence-internal `.`, `!` or `?` and the first inside a quote opened after a colon. An ellipsis stays as written and starts nothing.

### dayAware

`"dayAware": true` (zh only for now; owner feedback 2026-10-02: "if I finish many sessions a day many drills are repeated and many important recalls are not given"). Without it every planner ranks by `weakScore` (3 × lifetime misses − streak), which knows neither today nor time: each session drilled the same lifetime-weak units, a unit missed today could miss the next plans, and a mastered unit was never refreshed. Measured on zh by tests/day_sim_checks.js (8 Today sessions, one day, 85% right): session 8 had 61–65% of items in a kind already answered right that day; flag on, 0%.

**Storage (additive; only written with the flag).**
- `prog.day = { d, n, a }`: today's log. `d` the local date `YYYY-MM-DD`; `n` the drill ordinal (each drill started today, +1); `a[key]` per item key (`w:<word id>`, `c:<unit id>`, `s:<sentence id>`, `x:<script unit id>`) `{ r?: [kinds answered right], c?: n of the last right answer today, m?: n of the last miss today, mk?: [missed kinds not yet settled], ms?: prog.sn of the first of those misses, ma?: 1 once the item was asked again while they were pending, u?: prog.sn of the last right answer }`. A log from another date reads as a new day that carries over, per key, only the unsettled misses (`{mk, ms?, ma?}`, until settled or aged out, see Kinds) and the right kinds of the last `DAY_RECENT_SESSIONS` (2) sessions (`{r, u}`); a malformed log reads as a fresh day. The log is never validated at boot, so it can never send the progress record to backup. A cloze answer also logs the blanked word with kind `gap`; a right cloze neither counts as the word answered right nor settles its miss, and leaves the word record's `t`/`u`.
- `prog.sn`: the session ordinal, the planner's clock (owner 2026-10-02: "count by sessions rather than days"). +1 when Start today is tapped and for every drill started outside Today that drills words, sentences, character or script units (Test, Words-tab review or set drill, script practice); a drill of no unit (Sounds lessons), Today's own step drills and a resumed session never count. Missing or malformed reads as 0.
- `t` on `prog.w`, `prog.s`, `prog.chars.c` and `prog.script.u` records: day number (days since 1970-01-01, local date) of the last answer; `u`: `prog.sn` at the last answer. Missing on older records, which then rank as the longest unseen.
- None changes the meaning of any existing field; an engine without the flag keeps them all and ignores them (the engine before dayAware, 3d66aea, boots such progress with no backup: tests/migration_checks.js [day]).

**Kinds.** One partition for words, sentences and character units: production is recall, type (every typed variant), gap, gapType, charRecall, charPick; recognition is hear, read, charRead, charSound (core.js `DAY_PRODUCTION`). A miss stays in `mk`, across days, until a right answer in a later drill settles it: one in the missed kind, or in any production kind (a production answer settles a recognition miss too: owner 2026-10-03, a word missed by ear got no production ask for the rest of the week in 89% of cases). An easier kind never settles a miss (a recall miss answered right by ear stays pending), and neither does the in-drill retry. A missed kind the unit cannot be shown in on this device (hear with no voice or recorded audio, a cloze with no blankable word) counts as the nearest kind it can be shown in: the first renderable kind of the same partition, else the first renderable kind (core.js `dayMissKinds`, beside `daySettles`); planners only ask a unit in kinds it can be shown in (`dayWordCan`, `daySentenceCan`), and the logged kind is the one shown. Safety net: a miss asked again at least once (`ma`) and still pending `DAY_MISS_MAX_SESSIONS` (6) sessions after its first miss (`ms`) is dropped; the broken streak keeps the unit weak.

**Planning (core.js `dayPick`, `dayItemKind`).** Every candidate gets a tier: 0 missed (today or any earlier day), not yet settled, and this planner can ask a kind that settles it; 1 due: below the mastered streak and not right recently; 2 mastered and not right recently; 3 right recently, with a kind this planner asks still open; 4 right recently in every kind it asks, or a pending miss this planner cannot settle (a recall miss in Listen or Test Sentences by ear). A plan of n takes tier 0 (pending longest first, by `ms`, then weakest) up to ⌊0.6 n⌋ (`DAY_MISS_SHARE`, at least 1; the rest stay pending and fill only after tier 3), then the weak-word floor: words (keys `w:`, never units or sentences) of tier 1 (lowest streak, then longest unseen) until round(n × `DAY_WEAK_FLOOR` 0.4) of the plan are words, word misses already taken counting (8 of 20 in Review, 3 of 8 in Recall, 5 of 12 in Listen; owner 2026-10-03: weak words had lost their slots to unit misses, consolidation and refresh, 0.5 of 8 in Recall). "Right recently" is right today or in the last `DAY_RECENT_SESSIONS` (2) sessions (core.js; one constant), so the first session after midnight does not replay the evening's items. "Longest unseen" is fewest sessions since the last answer (`u`), then the oldest day (`t`). Then up to ⌈0.15 n⌉ consolidating character units (tier 2 with a streak below `bare`, longest unseen first: by weakScore alone a unit at streak 3–5 had no Review/Recall slot at all), then up to ⌈0.2 n⌉ of tier 2 (longest unseen first), then tier 1 (lowest streak, then longest unseen), then up to ⌈0.25 n⌉ of tier 3, then the rest of the consolidating units and of tier 2, the rest of tier 3, and tier 4 only when nothing else is left. The in-drill retry after a miss does not count as right for its kind, so the missed kind stays open. `dayItemKind` is the one place a unit's kind is decided for the day: a pending miss goes to a kind that settles it (the planned kind if it does, else its missed kind, else the nearest production kind, preferring one that settles every pending kind, so a hear and a recall miss go to recall, then one not right today); a unit already right today is asked in an open kind, production first. With the flag, the Today plan lines read "misses and due first" instead of "weakest first". Kinds and plan sizes otherwise come from the unchanged builders (kindMix, applyMissedKinds, hearableKinds).

**Sites.** Today Review, Listen, Recall and Sentences; Test Listen, Recall, Sentences and Characters; Words-tab review; the script practice drill. Unchanged: Learn (new words, new character sets: new material keeps its pace every session), the Words-tab set drill (the learner picked the set), lessons, placement, passages (already spaced by day), the Progress weak list (display only). Validation: `dayAware` must be a boolean. Ties are jittered by the caller's random source, so a plan is a function of (progress incl. the day log, date, draws); session resume records the drawn items as before.

### optsMix

`"optsMix": true` (zh only; owner 2026-10-02: "near the end of an hsk level, i can guess new words in drill by deducting which words must not be it ... Why not random pick?"). Off, every option builder keeps its level tiers (same level first) and draws exactly as before (tests/opts_mix_checks.js [3], control vs main 68930bd). A first version mixed learned and not-yet-learned options 1+2 / 2+1; review measured that a learner who rules out the other familiarity class still guesses right 40% of the time, so wrong choices now come from the answer's own stage.

- **Stages** (app.html `wordMix` / `sentMix` / `charCtx` pass a `stage` function; core.js stays pure):
  - word: 0 new/weak = in the Learn set being built (`withLearn`: Today's word set, the Words tab "Drill this set") or learned (`learnedWords`: any word record, placement `prov` and Read `d` included) with streak below `WORD_MASTERED` (3); 1 known = learned at or above it; 2 = never taught.
  - character unit: 0 = in the Learn set being built (Today's character set) or recorded below `characters.mastered`; 1 = at or above it; 2 = no record.
  - sentence: 1 seen (a `prog.s` record); 0 open (all its words learned) and not seen; 2 neither.
- **Rule** (core.js `mixPick`): candidates pass every old guard first (never a second right answer: same gloss, gloss's first two words, `syn`, homograph, homophone / `pronClash`; the `functionWords` class; `pronInGloss`). They are then ordered by hard preference, then stage: the answer's stage (a never-taught answer counts as 0, it is being taught), the other learned stage, never taught last. Builders whose class preference is a length the learner sees (`charOpts` for charPick / charRecall, `charSoundOpts`, `pronChoiceOpts`: code points / syllables) pass `nearFirst`: hard preference, stage tier, then length match, then the learn-order bucket (review 2026-10-03: a set-mate of the wrong length beat a same-stage item of the right length, guess by length 0.28-0.51); every other builder keeps bucket before class. Each group is shuffled; no level ordering. The old strict / non-strict passes take the first 3.
- **Learn-order buckets inside stage 0** (round-2 review: stage 0 lumped a Learn set of 9 set-mates with ~80 old weak words, so 92–94% of a Learn item's wrong choices were learned before today). For a new/weak answer the app passes a `bucket` function (app.html `mixSetOf` / `mixBucket`); stage-0 candidates rank by it, shuffled inside each bucket: 0 the answer's own set, 1 an adjacent set (±1), 2 the rest of stage 0. Known answers get no buckets.
  - word set: position in its level's list over `setSize`, counted on through the levels in order (the sets Learn teaches, in file order). While a Learn drill is built (`withLearn`), the Learn set is bucket 0 for its answers and every other word at least bucket 1.
  - unit set: position in taught order over `characters.setSize`: the stage order (`charStageUnits`), or under `learn: "lag"` the learn position of the unit's first word (a lag unit is taught once that word is learned), ties in stage order. Today's characters Learn set (the snapshot's `cset`, kept across a reload by `today.cu`) stays bucket 0 for its units for the rest of the Today session; its drill uses `withLearn` as words do.
  - Measured (tests/opts_mix_checks.js [1b], 5 learner shapes incl. HSK 1–3 with 80 weak words): no wrong choice learned before the answer's set wherever the set supplies 3 after guards; a learner who rules out never-taught, other-stage and non-set-mate options guesses 0.250. A weak answer on a later day draws from its own set first, then adjacent sets.
- **Hard preferences rank ahead of the stage**: `optsOneScript`'s "shown like the answer" (recall, cloze) and cloze article agreement (`prefer`).
- **Soft preference inside a stage, per builder**:
  - `meaningOpts` (read, hear, typed meaning's choice fallback; `charRead` through `charReadOpts`): same part of speech.
  - `wordOpts` (recall, typed word's choice fallback) and `gapChoices` (cloze): function words first for a function-word answer, then same part of speech.
  - `sentenceOpts` (sentence read / hear): translation length within 0.67–1.5× of the answer's, then sharing a word with it. Its same-level restriction is gone under the flag.
  - `charOpts` (`charPick`, `charRecall`) and `charSoundOpts` (`charSound`): same character count.
  - `pronChoiceOpts` ("How is it said?"): same syllable count. Its answer is a learned word, so its options are learned readings unless the stage runs short; it draws per set instead of the flag-off hash order.
- **Not changed**: placement (a measurement: its options stay level-tiered, review M1), passage questions and Sounds lessons (authored options), the script primer (`scriptOpts`; no pack sets both). Test tab items use the builders above.
- **Short stage**: when the answer's stage cannot supply 3 after the guards, the other learned stage fills in, then never-taught words (a fresh learner's first set uses its set-mates first: they are stage 0). An item rebuilt after a resume (not yet shown) sees Learn-set words by their records only; shown items replay from the session tape.
- **Storage**: none. Building options reads progress only; distractors create no record, count as no "seen" and never enter the day log.

### Pronunciation aids

Three pack fields and the sentence `ruby` turn on learning aids for the reading. Each is off unless the pack sets it, so every other pack renders exactly as before (tests/pron_aids_checks.js [7], tests/flagoff_snapshot.js).

- **Word taps in sentences** (a sentence drawn with its `ruby` tokens: always under `pronFirst`, and on a word-first characters pack once characters have started with mix on; also passage question reveals and results under `pronFirst`): each token with a known word is a tap target (Enter or Space from the keyboard). A tap shows the word's popover, the same one the Read tab uses (reading, gloss, show written), inside that sentence, and speaks the word only. A token whose surface contains its word and more (这个 for 这, 他们 for 他) is a phrase token: its popover heads with the surface's reading, show written gives the surface, and the tap speaks the surface. A token covering only part of its word (ja ruby over the written stem) keeps the word's headword. Escape closes any open popover or Read-tab gloss box and clears the tapped highlight, staying on the same view (inside a drill it does not quit); with nothing open it works as usual. The sentence itself is heard from its own speaker button, not by tapping the text. Question stimuli and answer options never carry taps. A tap has no progress effect. Sentence rows, reveal blocks, teach examples and passage reveals get taps; a sentence shown by its sentence `pron` line has no tokens and keeps the old whole-row tap.
- **`tones: "pinyin"`**: every displayed reading is coloured per syllable, as `<span class="t1">` to `t5` (tone 1 to 4, 5 for neutral), with light and dark colours. This covers word displays, sentence tokens and ruby, options, reveals, the Words list, popovers, teach rows, character items and lesson rows. A reading is split into syllables by the tone marks on its vowels and the pinyin syllable inventory (core.js `splitReading`, `splitSyllable`, `markSyllable`, `toneHTML`). A letter run that does not split into syllables (a Latin name, "OK") stays uncoloured.
- **`typing: "pron"`**: the production slot that alternates with recall (the same rule as other typing packs) is one of two typed items. The plan is unchanged. The item is picked by the slot's order among the plan's "type" slots: the first, third and later odd slots type the reading, the rest type the characters (core.js `typeSlotKind`, no randomness, so plans stay reproducible). Each card has a kind tag, its own heading and its own placeholder. A pack with `typedFrom` replaces this alternation with the rotation in "typedFrom and glossFocus" below.
  - **Type the pinyin** (the reading; "Type the reading" when `tones` is unset): the card shows the meaning and plays no audio before the answer, since audio would give the reading away. The input is a Latin one (`lang="en"`). Tones are optional. Tone marks or tone numbers are accepted; a neutral syllable may be written 5, 0 or with no digit, and an r-suffixed syllable with its digit after the r, or before it with the r bare, r5 or r0 (hsk's `yi1hui4r5`). Case, spaces and apostrophes are ignored, and v or u: stand for ü. The right letters with no tones, or with other tones, also count as right, and a "tones:" note gives the tone-coloured marked form. Other letters are wrong. This is core.js `checkPronTyped` ("ok", "tones", "tonesDiff", "wrong").
  - **Without `tones`** (ja: kana readings): "Type the reading", tag "reading", placeholder "reading…", and no tone note. The input takes the target-language attributes when the reading is not Latin script, so the kana keyboard comes up. The typed reading must equal the `pron` after `plainPronKey`: NFKC (half-width kana count as full width), katakana folded to hiragana on both sides (テレビ may be typed てれび and the reverse), then `normalizeTyped`, and letters, marks and digits are kept; everything else removed (spaces, the affix mark 〜, the middle dot ・), then NFC recomposed (a standalone voicing mark ゛ typed after its kana, は゛す, recomposes to ばす, matching バス). The long-vowel mark ー, small kana and voicing marks must match exactly: こうひい is not コーヒー, きやく is not きゃく. The verdict is "ok" or "wrong" only; pinyin syllable splitting and tone digits never apply (たべる1 is wrong).
  - **Type the characters**: the card shows the meaning, plays the word's audio once and has a replay button (as hear items). With `typedFrom` it is silent until answered (see "typedFrom and glossFocus"). The input carries the target-language attributes, so a phone keyboard switches to the pack's language. The written form or any `alt` is accepted (core.js `acceptTyped` with default options), and so are its affix-bare/slash-alternative forms (core.js `affixAlts`; see the `typing` row above). Katakana and hiragana are not interchangeable here: the written form is the spelling (テレビ). Without `tones` (a Latin reading excepted) the typed value is also NFKC-folded with ～ unified to 〜 before comparison (core.js `writtenTypedFold`), so half-width kana (ﾃﾚﾋﾞ) matches full-width (テレビ) and either affix-mark tilde matches whichever the written form uses.
  - The characters item needs the word's written form on display. Under `pronFirst`, a word below its character tier is shown by its reading only, so the learner has not seen its characters; that word gets the pinyin item in both slots, and the alternation resumes once the word reaches its tier. A word with no `pron` always gets the characters item. Both items record progress under the same `w:<id>` key as every other word item. The reading is never drilled on its own, typed cloze items never appear (the blank is written), and placement is unchanged.
- **`soundsReference: true`**: a collapsed Reference card below the Sounds lesson list. It lists every lesson row whose `say` is one character (its reading coloured, each reading once), grouped by lesson. Tapping a cell speaks that character. The zh lessons already cover every initial, final and tone, so the card is built from them, not from a separate chart file.

## pack/characters.json

Required when `pack.characters` is set (and must be absent otherwise). Holds the units, in teaching order within each level: sets are consecutive runs of `setSize` units of one level, in file order.

`[{ id, t, words, lv, reading?, hint?, say? }]`

| field | type | meaning |
|---|---|---|
| `id` | `c0001`…, unique | Progress key. Builders derive it from the unit's `words[0]` id (`w0416` → `c0416`), so ids follow word ids and are never renumbered when units are added or left out; a pack with gaps in unit ids is normal. |
| `t` | non-empty string | Written form, shown large. |
| `words` | `[wordId]`, non-empty | Linked words, ids from this pack's `words.json`. `words[0]` supplies the gloss and the audio. |
| `lv` | levelId | Must be one of `pack.levels[].id`, equal to the `lv` of `words[0]`, and covered by one of `pack.characters.stages[].levels` — decides which stage the unit belongs to. |
| `reading` | string | Optional. Answer for `charSound` and the ruby text. Defaults to the `pron` of `words[0]`. |
| `hint` | `[string \| null]` | Optional. A memory hint per character of `t` (aligned by code point, `null` for a character without one; at least one string, else leave the field out). Shown dimmed under the form on the teach card and in every unit item's reveal, one line per distinct character, prefixed with the character when `t` has more than one; a character already hinted on the same teach screen is not repeated (core.js `unitHints`, app.html `charHintHTML`). The word popover (a tapped sentence token or Read-tab word) shows the hints of the word's unit (`words[0]`) after the gloss, the same way, only while the word is shown written: under `pronFirst` a hint's characters would spell a form not yet taught. Results weak-word rows do not. Never on a stimulus or option: a hint names the meaning and parts, so it would answer charRead/charSound/charPick. Absent, nothing renders (byte-identical). zh: `tools/pack_from_hsk.py` from the committed tools/zh_hints.json (tools/zh_hints.py over Make Me a Hanzi, LGPL-3.0-or-later, credited in packs/zh/attribution.json; hand overrides in tools/zh_hints_overrides.json). |
| `say` | string | Optional TTS carrier, as words.json `say`. A unit is spoken through `words[0]` (whose `say` then applies), so the unit's own `say` is heard only for a unit with no word; packs/zh copies the word's. Never displayed. |

`tools/validate_pack.py` checks unique ids, that every `words` id exists, and that `lv` is a pack level, equals the level of `words[0]`, and is covered by a stage; a `hint` must be a list of non-empty strings or null, one per character of `t`, not all null.

## Script primer

Optional. `pack.script` plus `pack/script.json` turn on a **script primer**: one stage per `pack.script.stages` entry, placed before the first word level, that teaches a non-Latin writing system symbol by symbol (symbol to sound, recognition, then reading the pack's own first-level words). Absent, no script code path runs and `script.json` must not exist. Design of record: `docs/SCRIPT_PRIMER.md`.

```json
"script": { "stages":[{"key":"hira","label":"ひらがな"},{"key":"kata","label":"カタカナ"}],
  "setsPerSession":2, "mastered":3, "tts":true,
  "learnKinds":["symSound","soundSym"], "reviewKinds":["symSound","soundSym","compose","wordRead"],
  "testKinds":{"symSound":35,"soundSym":25,"wordRead":25,"symType":15} }
```

| field | type | required | meaning |
|---|---|---|---|
| `stages` | `[{key, label}]`, non-empty | yes | Path order. `key` is the `st` of its units, unique; `label` is shown on the stage strip, Progress and the Script tab. |
| `setsPerSession` | positive int | no (2) | Script sets Today's Learn step offers per session: the first is taught, the rest behind "One more set". |
| `mastered` | positive int | no (3) | Streak at which a unit counts as mastered. |
| `tts` | bool | no (true) | `false` treats every `say` as absent: `soundSym` shows the `roman` as text and `wordHear` becomes `wordRead`. A unit's recorded `audio` still plays. |
| `learnKinds` | kinds, non-empty | no (`symSound`, `soundSym`) | One Learn item per kind per unit, among the kinds the unit can carry (below). |
| `reviewKinds` | kinds, non-empty | no (`symSound`, `soundSym`, `wordRead`) | Review draws one at random per unit. |
| `testKinds` | `{kind: weight}` | no (`symSound` 35, `soundSym` 25, `wordRead` 25, `symType` 15) | The Script tab's practice mix. |

Kinds are `symSound`, `soundSym`, `symType`, `compose`, `formFind`, `formMatch`, `wordRead`, `wordHear` (`docs/SCRIPT_PRIMER.md` §2). A unit carries a kind only when it has what the kind needs: the three sound kinds need `sound` not false; `compose` needs `syll`; `formMatch` needs `joins`; `formFind`, `wordRead` and `wordHear` need `ex`. A `sound:false` unit gets `wordRead` in place of the sound kinds in Learn. An option kind also needs at least 4 distinct options drawn from all the pack's units, or it is never asked of that unit.

### pack/script.json

Required when `pack.script` is set, absent otherwise. `{units, notes?}`.

| unit field | type | meaning |
|---|---|---|
| `id` | `^[a-z]{2,3}-[a-z0-9-]+$`, unique | Progress key (`prog.script.u`), stable, never renumbered. Not the glyph: one glyph in two roles is two units. |
| `st` | stage key | One of `pack.script.stages[].key`. |
| `set` | int ≥ 1 | Teaching set within the stage; each stage's sets are contiguous from 1. File order is the order within a set. |
| `group` | string | Distractor family (vowels, a dot family, a kana row). |
| `t` | non-empty string | The glyph. A teach card may show two forms separated by a space ("Д д"); items use the last. |
| `name` | string | The letter's name. Dropped from the teach card head and reveal when it only repeats `roman` ("ka" \| "ka"), compared trimmed and case-insensitively; core.js `scriptUnitHeadName`. |
| `roman` | non-empty string | Canonical romanisation, the answer to `symSound`. |
| `alt` | `[string]` | Other accepted romanisations (typed `symType`). Options ignore a one-way alt (ko ㄱ alt `k` is drilled against ㅋ); two units that accept each other's roman (fa غ gh/q, ق q/gh) are never each other's distractor. |
| `say` | string | TTS carrier: the bare glyph, a carrier syllable or the name. Absent when unspeakable. |
| `audio` | URL | Recorded clip; beats `say`, and plays even with `tts` false. |
| `sound` | bool, default true | `false` for silent or modifier units. |
| `note` | string | One-line sound note. Dropped the same way when it only repeats `roman`; core.js `scriptUnitNote`. |
| `confuse` | `[unitId]` | Hand-listed confusables: preferred distractors, and the padding for early sets. |
| `ex` | `[[wordId, roman]]`, 1–3 | Example words from this pack with their romanisation. The glyph occurs in the word's `w` or `pron`. |
| `syll` | `[{t, parts, roman}]` | Composition examples for `compose`; `parts` are glyphs of units at or before this set, `t` occurs in a first-level word. |
| `joins` | `"dual"` / `"right"` | Joining letters of a right-to-left pack. Forms are drawn by Unicode shaping from the letter plus a zero-width joiner. |
| `base` | unitId | The unit this one is a variant of (a mark added, the other syllabary); the teach card shows base → variant. |
| `italic` | string | The glyph's italic form when it differs; the teach card shows it. |

`notes`: `[{st, set, h, body}]`, rule cards shown with the teach cards of that stage's set. `h` and `body` are plain text (escaped).

**Example words** are shown in the script being taught: a word whose `w` uses letters outside the primer's units while its `pron` is written entirely with them (ja kanji words) is shown, spoken and answered by its `pron`; otherwise by its `w`.

**Progress.** `prog.script = {v:1, u:{[unitId]:{r,w,s}}, skipped, skip:{[stageKey]:bool}, choiceSeen, notice}`, present only with `pack.script`. `skipped` turns the whole primer off and `skip` one stage; an off stage leaves the path, Review and Test, and its records are kept. Taught, done and mastered are derived: a set is taught and a stage done once every unit has a record; mastered is streak ≥ `mastered`. Stored progress with word records and no `script` field (a learner from before the primer) normalizes to `skipped:true, choiceSeen:true, notice:true`: the primer starts off, with a one-time notice that it can be turned on in Progress. Fresh progress starts with the primer on and the choice card unanswered. Turning the primer or a stage on in Progress clears `notice`. `prog.script` is created whenever `pack.script` is set, even when `script.js` has no units and the primer is off; it is then inert.

**Validation** (`tools/validate_pack.py`): `script.json` exists exactly when `pack.script` does; `pack.script` field types and known kinds; unit ids unique and well-formed; `st` a stage key, `set` an int ≥ 1, each stage's sets contiguous from 1, every stage non-empty; `t` and `roman` non-empty, `sound` a bool, `alt` strings; `confuse` and `base` known ids; `ex` word ids exist, from the first or second level (the second is a warning; a unit of a later stage may also use the third level, with a warning, because a later stage such as ja katakana teaches a script the first levels barely use), the roman non-empty and the glyph in the word (compared after compatibility decomposition and lower-casing, with positional letter variants folded); `syll.parts` glyphs of units at or before the set and `syll.t` in a first-level word (for a later stage, after folding katakana to hiragana); `joins` only in an `rtl` pack; `notes` on a known stage set. Warnings: a unit with no `ex`; two units of one group with the same `roman` and no `confuse` link; a sounded unit with no `say` while `tts` is on; an `alt` equal to another same-stage unit's `roman` (typed answers would accept the unit as that letter's sound), except between units of the same glyph or units that accept each other's roman.

## words.json

`[{ id, w, en, lv, pos?, rank?, pron?, alt?, forms?, audio?, say?, syn?, typedSyn?, noTypedMeaning?, pronInGloss? }]`, in teaching order within each level. Learn teaches the level's next `setSize` not-yet-learned words in file order; learned means the word has a progress record, so reordering or editing a level on republish never shifts what counts as learned (README "What the app does"). The Words tab browses consecutive runs of `setSize` words in file order.

| field | type | meaning |
|---|---|---|
| `id` | string, unique | Stable id. Progress is keyed by it, so never renumber a published pack. The zh pack uses `w0001`…. |
| `w` | string | The word as written. It is shown, spoken by TTS, and is the typed or recalled answer. |
| `en` | string | English gloss. It is the answer label in meaning items. Distractors avoid the same gloss and the same first two gloss words. |
| `lv` | levelId | Must be one of `pack.levels[].id`. |
| `pos` | string | Optional part of speech. Recall and cloze distractors prefer the same `pos` and level. |
| `rank` | number | Optional frequency rank (1 = commonest). Every packbuilder pack shipped as of 2026-09-28 is already in this order, so a rebuild moves no word. A pack built elsewhere (packs/zh has no `rank`) keeps its file order. |
| `pron` | string | Optional pronunciation (pinyin, IPA). It is display-only, except that `typing: "pron"` makes it a typed answer. |
| `audio` | URL string | Optional recorded clip of `w`, with the same rules as `sentences.json` `audio`. Every place the app speaks the word plays it instead of TTS, and a word with a clip can be heard with no voice (Listen items, taps, placement, the script primer's example words; app.html `sayWord`/`canHearWord`). |
| `say` | string | Optional TTS carrier spoken in place of `w` wherever the app speaks the word (app.html `sayWord`, core.js `wordSay`; the script primer's example words too). Never displayed, typed or searched. A recorded `audio` clip beats it; a clip that fails falls back to TTS of `say`. Sentences are spoken as written (the TTS reads them in context). Use: zh polyphonic characters a TTS misreads alone (还 hái is spoken huán; `say` 孩), built by tools/zh_say_scan.py into tools/zh_say.json, table in docs/ZH_SAY.md. Validator: a non-empty string other than `w`. |
| `alt` | `[string]` | Optional accepted alternative typed answers, such as a feminine form or other spelling. It is also used to find the word in a sentence for cloze when `w` itself does not appear. Inflected forms that should only locate the word, never be typed, go in `forms` (a pack builder routes each surface with its `alt_kind` hook, docs/PACKBUILDER_HOOKS.md; cloze options never offer a distractor whose `w` or `alt` is the blanked text, core.js `gapChoices`). **Convention:** when `w` carries an article or clitic (`il gioco`, `l'anno`, `le/la médecin`), put the bare lemma first (`alt[0]` = `gioco`), or, when the bare lemma is not a typed answer (`lever` for `se lever` is another verb), put it in `forms` and name it in `bare`. The engine treats the marked bare form (`bare`, else `alt[0]`) as the word's bare form only when it is a whole trailing token of `w`, after a space or apostrophe (core.js `bareForm`). Without one, a leading article from the pack's `pos:"art"` words (their `w`, alts and `forms`, including a/b pairs like `le/la`) is stripped instead. **Cloze article rule:** the blank never includes an article. When the matched form carries one (`l'église`, `la iglesia`, an alt such as `l'acqua`), the article stays visible and only the bare rest is blanked (`allons à l'____`, `Bevo l'____.`). Every multiple-choice option, answer and distractors alike, is shown by its bare form (`église / gare / fruit`), never `la gare`. Prefer alts that are the word alone. Examples for a taught word prefer sentences where `w`, then an alt or a `forms` entry, is visible. |
| `forms` | `[string]` | Optional inflected surfaces of the word (ja 食べた, 食べない, 食べます for 食べる; する → した, して). Never accepted as typed answers and never counted as homograph surfaces for distractors (core.js `surfaces`, `acceptTyped` and its collision guard read `w` + `alt` only). Used everywhere the word is located inside text, exactly like `alt` (core.js `textForms`): cloze location and protection (`locateWord`, `packSurfaces`), example-sentence tiers and highlighting, passage fallback matching (`passageSegments`) and Words search. Because forms are not homograph surfaces, a cloze's options also drop any distractor whose `w` or `alt` is the blanked text itself (core.js `gapChoices`: する blanked at した never offers 下, written した). Validator: a list of non-empty strings; a form equal to `w` or an `alt` is a warning. The forms of a `pos:"art"` word are pack articles like its `w` and alts (core.js `packArticles`: German die/den/dem as forms of der, French la/l'/les of le). Builders emit it through packbuilder `LanguageSpec.alt_kind`, applied by `core/words.py` `split_alt_forms` (ja, ko, fa, ar, hi, id; es/it/fr gender pairs and pronominal bases; since 2026-09-28 also article declensions in de/fr/es/it). |
| `syn` | `[id]` | Optional. Words sharing an accepted meaning; never each other's wrong option. Generated (zh: tools/zh_gloss.js). See "Synonyms". |
| `typedSyn` | `[id]` | Optional, within `syn`. Words this word's whole gloss also fits; typing one on a meaning stimulus is right. See "Synonyms". |
| `noTypedMeaning` | `true` | Optional. The gloss is only explanations (particle, classifier, marker): never asked as a typed meaning. See "Synonyms". |
| `pronInGloss` | `true` | Optional. The gloss spells the toneless reading (北京 "Beijing"): reading and meaning are never stimulus and answer for each other. See "Synonyms". |
| `bare` | string | Optional gap label for a `w` that carries an article or clitic whose bare lemma is not a typed answer, so it sits in `forms` rather than at `alt[0]` (fr `se lever`: `bare` `lever`, `forms` `["lever", ...]`). core.js `bareForm` and `articleCut` read it before `alt[0]`, and only when it is a whole trailing token of `w`. Packs without it behave as before. Validator: a non-empty string; equal to `w`, or not a trailing token of `w`, is a warning. Set by the fr builder (`langs/es.py` `mark_alt_forms` `bare_form`). |

## sentences.json

`[{ id, t, en, lv, words, pron?, audio?, ruby?, spans? }]`

| field | type | meaning |
|---|---|---|
| `id` | string, unique | Progress key. |
| `t` | string | Sentence text in the target language. It is shown, spoken, and used for cloze. |
| `en` | string | Translation, used as the answer label and in sentence distractors. |
| `lv` | levelId | Level. A sentence becomes available once all its `words` are learned, or once the learner is past this level. |
| `words` | `[wordId]` | Word ids used in the sentence, resolved at pack-build time with no runtime lookup. A cloze candidate must pass four rules. It is at the sentence's own level. It is not a function word. It is not repeated in `words`. Its forms (`w` plus every `alt` and every `forms` entry) appear exactly once in `t` overall, where overlapping hits count as one. That occurrence must also not sit inside a longer pack word or compound, such as 为 inside 为什么. |
| `pron` | string | Optional display-only pronunciation of the whole sentence. |
| `audio` | URL string | Optional recorded audio. When present it plays instead of TTS. Relative URLs resolve against the built HTML file's location, not the pack directory, so ship audio beside the built page or use absolute URLs. A clip that fails to play (offline and not cached, a 404) falls back to TTS when a voice exists, else a short hint is shown. `packbuilder audio` writes relative content-addressed `audio/…/<id>.<sha8>.opus` URLs and never changes an absolute (Tatoeba) one or a relative one it did not write. |
| `ruby` | `[[start, end, reading, wordId]]` | Optional, only meaningful with `pack.characters`. Per-token readings for characters tiering: each tuple is a UTF-16 offset range into `t` (`end` exclusive, same convention as `passages.json` `spans`), the reading text for that range, and the `characters.json` unit's `words[0]` id that range belongs to (so 这个 maps to its base word), or `null` for a token of no unit word (a name, a word the sentence does not link or that has no unit): it follows streak 0, so it shows its reading under `pronFirst` and the ruby tier otherwise. ja writes a token for every kanji (langs/ja.py `sentence_ruby`), so every sentence can show every kanji with a reading. Tuples are sorted, non-overlapping, and each covers non-blank text without splitting a surrogate pair. A sentence with `ruby` renders `<ruby>t<rt>reading</rt></ruby>` per token below the `bare` tier and `<ruby class="bare">t<rt>reading</rt></ruby>` at or above it, with that `<rt>` hidden (`visibility:hidden`), so a token's width and the line's wrapping never change across tiers. With pron hidden or the mix preference off the sentence renders as plain text, as without characters. |
| `spans` | `[[start, end, wordId]]` | Optional. Where each linked word sits in `t`, written by the builder from its tagger tokens, so an inflected surface no `w`/`alt`/`forms` entry lists (sw anatumia for kutumia, ru книгу for книга) is located. Same shape and rules as `passages.json` `sentences[].spans` and the same offset convention as `ruby` (UTF-16 code units, `end` exclusive), except there is no 4th `gloss` element: sorted, non-overlapping, each `wordId` in `words`, a multi-token unit (kuwa na, per favore) one span, a word occurring twice two spans. **Exactly one span for a word makes it the cloze target**: core.js `locateWord` (so `gapMatch` and `gapCandidateIndices`) returns that span after the usual reduplication/clitic extension, unless a `w`/`alt`/`forms` surface of the word is also visible outside it (then null: blanking would leave the answer in sight). `gapMatch` still cuts a leading article and checks `trailingCut` on the span text, and still rejects a span inside a longer pack word. **Two or more spans make the word no cloze target** (null, no regex fallback, which could blank an unrelated surface while the spans stay visible). **No span for the word keeps the regex path** over `w`/`alt`/`forms`. Highlighting (`highlightParts`) bolds every span of the word when it has any, else its surface matches. The Words-tab example chooser (`exampleSentences`, words with `forms`) maps a span's text to the first form (`w` first) it equals or shares a trailing token with (libro under il libro is the headword), else uses the text itself. Invalid spans (out of bounds, blank, splitting a surrogate pair, `wordId` not in `words`, overlapping an earlier span) are ignored, as in passages. A sentence without `spans` behaves exactly as before (tests/sentence_spans_checks.js). The builder must keep spans sorted by `start` and give every linked word it can place a span: `validate_pack.py` reports the unspanned count as one pack-level warning. |

**Cloze answers and the blanked word.** A cloze answer is scored on the sentence record (`prog.s`). It also sets the blanked word's missed kind `k` on a miss: `type` for a typed gap, `recall` for a choice gap. A pass clears `k` when it equals that kind. The word's `r`, `w` and `s` are left alone, and a word with no record gets none (core.js `markMissKind`; README "What the app does").

## lessons.json

Optional. The shape is unchanged from hsk's `LESSONS`.

```
[{ id, title, blurb,
   cards: [{ h, body, rows?: [[col1, col2, col3]], say?: [string] }],
   items: [{ t: "mc", q, say?, opts: [string], a, rv? }] }]
```

- `body` is trusted HTML written by the pack author. Everything else is escaped.
- `rows` render as three columns: pronunciation, word, gloss.
- `say` entries are spoken by TTS on tap.
- An item's `say` is played when it starts. With no usable voice, an item whose `q` already contains the `say` text runs as is. An item whose `say` text contains the answer is skipped, with a notice. Any other item shows the `say` text in place of the audio. This is core.js `lessonSayMode`.
- In `items`, `t` must be `"mc"`. It is the only item type, and the engine skips any other. `a` must be one of `opts`, and the options must be distinct. `rv` is the text revealed after answering.

## passages.json

Optional. When present and non-empty, the app shows a **Read** tab. Without it nothing changes.

```
[{ id, lv, title, titleRuby?, text, src?,
   sentences: [{ t, en, words: [wordId], spans?: [[start, end, wordId]], ruby?: [[start, end, reading, wordId|null]], audio? }],
   questions: [{ q, en?, type: "mc"|"tf", options: [4 strings] | null, answer, words: [wordId], sentence,
                 ruby?, optionsRuby?: [ruby per option] }] }]
```

| field | type | meaning |
|---|---|---|
| `id` | string, unique | Progress key (`prog.read.done`). Never renumber a published pack. Convention `p0001`…. |
| `lv` | levelId | Must be one of `pack.levels[].id` (`"A1"`, `"A2"`, `"B1"`; zh would use `"1"`…). |
| `title` | string | Target-language title, shown in the passage list. |
| `text` | string | The full passage. Each `sentences[].t` should appear in it verbatim (warning otherwise). Length in the list is whitespace tokens of `text`, or the linked word count when `pack.spaced` is false. |
| `src` | string | Optional provenance, e.g. `"gen"` for build-time generated passages. Not shown. |
| `sentences[].t` | string | One sentence of the passage, rendered in order. |
| `sentences[].en` | string | English translation, shown in question feedback and results. |
| `sentences[].words` | `[wordId]` | Linked pack words. Each is tappable for its gloss: at its `spans` when it has any, otherwise wherever its `w`, an `alt`, a `forms` entry or its bare form is visible in `t` (core.js `passageSegments`, longest match wins, so 为什么 beats 为, and a surface hit never covers a span). A linked word with neither is shown as a chip under the sentence, so every linked word stays tappable. |
| `sentences[].ruby` | `[[start, end, reading, wordId]]` | Optional, only meaningful with `pack.characters`. Same format, rules and rendering as `sentences.json` `ruby`, per passage sentence; a token crossing a tap-span edge renders plain. As in `sentences.json`, `wordId` may be `null`: a token of no pack word (a name, an out-of-pack word, zh aspect 过) with no unit, so it follows streak 0 (its reading under `pronFirst`, the ruby tier otherwise). zh writes a token for every hanzi (`packbuilder passages`, langs/zh.py `passage_ruby`) and ja one for every kanji (langs/ja.py `passage_ruby`, readings in hiragana over the kanji only, okurigana outside: 悪かった is 悪 わる), so a pronFirst passage never shows a hanzi or kanji below mastered. |
| `titleRuby` | ruby list | Optional, same tuple format for `title` (wordId `null` or a characters.json unit's `words[0]`; no words list applies). Rendered under `pronFirst` (app.html `pfRubyText`): the passage list button, the Today plan's Read row, the passage heading and the results heading show the title by the sentence tier rules, readings tone-coloured with `tones`, a `null` token by its reading. The heading and the Read row get a show-written tap; list buttons do not. Without `pronFirst` (or without `titleRuby`) the title shows as written. |
| `questions[].ruby` | ruby list | Optional, same format for `q`. Rendered under `pronFirst` like `titleRuby`, on the question screen and the results screen, with a show-written tap. No word taps. |
| `questions[].optionsRuby` | `[ruby list]` | Optional, mc only: one ruby list per `options` entry, same index (a list may be empty). Rendered under `pronFirst` like `titleRuby` inside each option button, with no show-written tap and no word taps (the button is the tap target). An empty list shows the option as written. |
| `sentences[].audio` | URL string | Optional recorded clip of the sentence, with the same rules as `sentences.json` `audio`. The Read tab's per-sentence read-aloud plays it, also with no voice. A passage whose every sentence has one can run as a listening pass with no voice (see "Listening pass" below). |
| `sentences[].spans` | `[[start, end, wordId, gloss?]]` | Optional. Where each linked word sits in `t`, as written by the builder from its tagger tokens (`packbuilder passages`), so inflected forms (mele, compra, va) are tappable in place. Offsets are UTF-16 code units (JavaScript string indices; equal to character indices for text without characters above U+FFFF), `end` exclusive. Spans are sorted and do not overlap, each `wordId` is in `words`, and a word may have several spans (one per occurrence). A multi-token unit the builder links as one word (per favore) is one span. `words` stays the full list: a word without a span falls back to surface matching, and packs without `spans` render exactly as before. Invalid spans are ignored by the app. Optional 4th element `gloss`: a non-empty display-only string shown in the tap-to-gloss popover instead of the word's `en` (fallback: span gloss, then the word's gloss). zh uses it for phrase units linked to a head word (越来越 -> 越 "more and more", 开车 -> 开 "to drive") and, in zh and ja, for display glosses from `gloss_display.json` (`packs/zh/gloss_display.json`, `japanese/tools/gloss_display.json`: a sense list per headword). It never changes `words`, drills, weak words or progress; a span without it, and a pack without it, render exactly as before. `sentences.json` has the same `spans` field without `gloss`, used for cloze and highlighting. |
| `questions[].q` | string | Target-language question. |
| `questions[].en` | string | Optional English translation of `q`, shown under it. |
| `questions[].type` | `"mc"` or `"tf"` | Multiple choice or true/false. |
| `questions[].options` | 4 strings or `null` | mc: exactly 4 distinct target-language options, shown shuffled. tf: `null` or absent. |
| `questions[].answer` | int or bool | mc: index 0–3 into `options`. tf: `true` or `false`. |
| `questions[].words` | `[wordId]` | Words the answer hinges on. A wrong answer charges them. May be empty (warning). |
| `questions[].sentence` | int | Index into `sentences` of the source sentence, highlighted in feedback and results. |

**Unlocking.** A level's passages unlock once 70% of that level's words are learned (core.js `READ_UNLOCK`, `readingLevels`). The unlock is stored in `prog.read.unlocked` and stays even if the count later drops. A locked level shows the threshold and the learned count.

**Today.** Passage reading is the last Today stage, after Sentences (core.js `nextReadItem`, app.html `todayStep` step 5). It runs one passage per session: the first not-done passage at an unlocked level, in pack order (`suggestPassage`, reason `new`). When every unlocked passage is done, it offers a re-read (reason `reread`). The candidates are passages whose latest attempt missed a question (`done[id].sc < n`). The one completed longest ago is chosen, and only once at least 7 days have passed (`READ_REREAD_DAYS`). Ties go by pack order. With no candidate the stage is absent: no plan row, and the session ends after Sentences. The plan lists it as `Read | 1 passage: <title> (<level>, N words)`, or `1 passage to re-read: ...`, or `Listen | 1 passage to listen to: ...` for a listening pass. The title renders as target-language text (reading-first under `pronFirst`), and the rest goes through `ui()`. The stage uses the Read tab's screens. Only two things differ: "Skip today" replaces the passage-list link, and the results end with Continue instead of "Add to review" / "Back to passages". Continue applies the ticked weak words (all by default) as "Add to review" does, then finishes the session. The passage is recorded in `prog.read.done` exactly as a Read-tab completion is. "Skip today" records nothing, so the passage is not done and comes back next session. The session still counts as usual. The Read tab stays for free reading. **Re-entry.** A Read-tab passage survives a tab switch: returning to the tab resumes it on the same screen. A tab switch ends the Today stage with the rest of the session. Returning to a passage screen, or a late voice list re-mounting it, restores the screen and speaks nothing again: option order, shown translation or question, the passage toggle, an answered question's reveal (no replay of the source sentence), and on results the unticked weak words and a done "Add to review" (it cannot apply twice). A question first mounted without a voice is spoken when a voice arrives, once, only while unanswered. Other screens with state a re-render would lose are left alone on a voice change: a drill item, a Today teach screen between steps, and a placement run or its result. Packs without passages render Today byte-identically to before.

**Flow.** Reading screen: sentence by sentence, tap-to-gloss on linked words (each tapped id is logged), optional per-sentence read-aloud when speech works or the sentence has `audio`. "Done reading" starts the questions, one at a time, with the passage hidden behind a "Show passage" toggle. Opening it before answering is logged for that question. Each question is spoken (TTS only, questions carry no `audio` field) with a Replay button when speech works; its English translation (`questions[].en`), when present, stays behind a "Show translation" tap rather than showing by default; a peek before answering is noted (" · translation shown") on that question's results line, but unlike reopening the passage, it does not feed `passageWeakWords`. The verdict ("Right." / "Not quite.") and its source sentence sit under the options, above the "Show passage"/"Hide passage" toggle; answering with the passage open brings the verdict into view instead of scrolling to Next below the passage, and with `readAnswerBlock` Next moves up under the verdict too (owner feedback 2026-10-02). Feedback highlights the source sentence and plays its clip or TTS (also Replay-able), cancelling the question's own speech first, with a Replay per source sentence again on the results screen (no autoplay there).

**Listening pass.** A Today re-read (reason `reread`) runs as a listening pass when this device can hear every sentence of the passage (each has `audio`, or a TTS voice is usable: app.html `canListenPassage`, per device) and the latest attempt was not itself a listening pass (`done[id].l`), so re-reads alternate listen, read, listen (core.js `readPassMode`). Otherwise, and for every first pass and Read-tab passage, it is the reading pass above. The voice is re-checked when the stage starts. The listening screen shows a numbered play row per sentence instead of its text (clip, else TTS), "Play all" (the sentences in order, each after the previous one ends; Stop, a row tap, or leaving the screen, a tab switch included, stops it and the current sentence at once) and a "Show text" toggle that shows the ordinary passage rows with tap-to-gloss; using it is logged (`peekText`). "Done listening" starts the questions. While a voice is usable, ceil(n/2) of the questions are audio-only: spoken on mount as usual, with the question text and its "Show translation" behind a "Show question" tap, which is logged for that question when used before answering; answering reveals it too, unlogged. The pick is core.js `listenAudioOnly`: a question order shuffled by a seed from the passage id, rotated by the previous attempt count `x`, first ceil(n/2) taken, so with two or more questions consecutive re-reads never hide the same set. With clips and no voice no question is audio-only, since questions have no clips. Options, feedback, "Show passage" and weak words are unchanged. Results add a "Listening pass" line (and "Text shown while listening" after Show text) and ` · question shown` on each question whose text was revealed before answering. The attempt is recorded with `l: 1`.

**Weak words.** The results screen lists the union of tapped words, the `words` of wrongly answered questions, and the `words` of questions answered after reopening the passage (`passageWeakWords`). Each has a checkbox, ticked by default, except a word listed only for reopening: it shows "looked back" as information, with no checkbox, and is never applied (weight 0, user 2026-09-28). When every listed word is looked-back only, the list, its heading and "Add to review" are not shown. "Add to review" adds misses to `prog.w[id].w`: 2 for tapped or wrong, the largest reason winning (`READ_WEIGHT`, `applyWeakWords`). The streak resets as for any miss, so `weakScore` ranks them first in the next review. A word not yet learned is flagged `d` (drilled ahead), which puts it in the review pool. As with a Words-tab drill-ahead, a `d` word then counts as learned everywhere, including the 70% unlock threshold. This is intended. The passage is recorded as done in `prog.read.done[id] = {sc, n, d, x, l?}`: latest score, question count, date, attempt count, and `l: 1` when that latest attempt was a listening pass (absent for a reading pass).

**Progress.** `prog.read` (`{unlocked: {levelId: 1}, done: {passageId: {sc, n, d, x, l?}}}`) is created on first use, exported and imported with the rest, and checked by `validateProgShape` (`l`, like `sc`/`n`/`x`, must be a number when present). Stored progress without it loads unchanged, and so do `done` records from before listening passes (no `l`). The Progress tab shows passages done and the average latest score per level.

**Script display.** Titles, passage sentences, questions, mc options and gloss words carry `lang`, `dir="rtl"` and the pack fonts, as everywhere else. English translations and True/False labels do not. In RTL packs the tap-to-gloss popover itself is `dir="rtl"` with `text-align:start`, so the tapped word sits at the right edge and its `pron` and English gloss follow in reading order. Those two stay isolated left-to-right runs (`dir="ltr"`).

## legacy.json

Optional, required when `pack.legacy` is set (and must be absent otherwise). Maps an old standalone app's own ids to this pack's ids, for a one-time progress migration (`docs/HSK_MERGE.md` §4) that this schema and its tooling only carry the data for; the migration function itself lives in `engine/core.js`.

```json
{ "w": {"你好": "w0028"}, "s": {"你好，我是学生。": "s0001"}, "c": {"你": "c0001"} }
```

An object with up to three optional keys, each a map from an old-app string key to an id in this pack:

| key | maps to | meaning |
|---|---|---|
| `w` | `wordId` | Old word key (e.g. the hanzi surface) to this pack's `words.json` id. |
| `s` | `sentId` | Old sentence key (e.g. the sentence text) to this pack's `sentences.json` id. |
| `c` | `unitId` | Old character key to this pack's `characters.json` id. Only meaningful with `pack.characters`. |

`tools/validate_pack.py` checks that every mapped id exists (in `words.json`, `sentences.json`, or `characters.json` respectively) and warns if a map's values are not unique.

## Session resume

Not a pack field: every pack gets it (app.html "session resume", core.js `sessionKey`, `sessionHash`, `sessionStale`; tests/session_resume_checks.js). A drill or passage in progress survives an app-tab switch and a page reload.

- **What resumes**: Today (Review, Learn drill, Listen, Recall, Sentences, the Read stage, the stage between drills, a Learn teach screen), Test drills, the Words-tab set drill and review, Sounds lesson and script drills, and the Read passage flow (passage screen, each question, results). Placement does not. The item on screen comes back with the same options in the same order; the queue keeps its order, kinds and labels; right/seen counts and the missed list are kept; a typed item missed twice comes back as its choice counterpart. A results screen comes back with its Continue, and Today then goes on to the next stage.
- **Tabs**: each app tab keeps its own session, so a Test or Words drill or a passage started while a Today session is under way never drops it. Leaving a tab keeps its session; returning to it resumes. Tapping the tab already open, Escape in a drill and "‹ passages" leave to the tab's home screen and keep the session: that screen offers "Resume drill" / "Resume passage" at the top, and Today's Start button reads "Resume today" and resumes. Starting another drill in the same tab replaces that tab's session. A finished session (results Continue, "Back to passages", the end of Today, or a re-tap of the tab while a Test/Words/Sounds drill's or a Read-tab passage's results show) is dropped; a Today drill's results are mid-session and stay. Placement does not resume.
- **Boot** restores exactly what was on screen when the page went away: the session that was showing (same item), else the home of the tab that was showing. A session the learner left (tab switch, re-tap, Escape, ‹ passages) is never opened at boot; it comes back through its tab, its Resume button or "Resume today".
- **Storage**: one JSON value under `vocab_<key>_session` in localStorage, else in memory for the page's life. It survives a reload, an app switch, a tab the phone discarded, a closed and reopened tab and a home-screen relaunch (sessionStorage, used before 2026-10-02, is empty in a new browsing context, so those restarted). The value is the latest record with the other app tabs' records under `park: { <tab>: record }` and `view: { tab, live }` (the tab on screen at the last change; `live` when its session was showing). Two open tabs of one site share it: the second opens on the first one's item, and the last writer wins. Each record is `{ v, build, t, fp, tab, today?, drill? | rd? }`: `drill` holds each queued item as its builder name and arguments (words, sentences, units and lesson items by id or index) plus, for the item on screen and items already shown, its builder's random draws, replayed on rebuild: a core.js call that drew is kept as its result (`{ m, r }`, e.g. the three distractor ids of `meaningOpts`), other draws as numbers; the missed list holds each missed item's recipe once per key (its reveal is rebuilt); a Today script-Learn results screen names itself (`sm`) so "One more set" survives. A 40-answer Test drill with every item missed once stays under ~6 KB (zh, es); `rd` is the passage state with the passage by id; `today` holds the stage index and the Read-stage pick. Saved on every item shown and every answer, on a tab switch and on page hide.
- **Voices after boot**: a hear item rebuilt while the pack's language has no listed voice comes back as a read item with the no-voice notice; when a voice arrives (voiceschanged), every such item not yet answered is rebuilt as a hear item with the same options, and the one on screen is shown again, playing.
- **Characters set** (`characters.learn: "lag"` only): `today.cu`, the unit ids of the Learn step's characters set, so the resumed step teaches the same units (sets are dynamic there).
- **Progress is never in it**: answers are written per answer to `vocab_<key>` exactly as before, so a dropped record loses nothing recorded. No progress field is added or changed.
- **pauseNew**: a resumed Today session reads the pause at its Learn and Read steps (see "pauseNew").
- **Dropped silently** (`sessionStale`): a record from another build (the build id build.sh writes into app.html's `VE_BUILD`, a cksum of engine + pack sources, known while the page still parses; dev mode uses `dev`; plus a pack fingerprint), saved more than 12 h ago (or over a minute in the future), or, at boot, whose progress fingerprint no longer matches the stored progress (the raw stored string or its normalized form; something other than this engine changed it). The fingerprint is `sessionHash` of the progress as last stored: every progress save by the page (answers, Read unlocks, settings) re-fingerprints all its records, so the page's own writes never invalidate a parked session. Import and "Reset all progress" drop every record. An unreadable record or one that no longer rebuilds is dropped the same way.

## Validation

`python3 tools/validate_pack.py <packdir>` checks the following. Exit status 1 means at least one error.

- Required fields and types for every file.
- Unique ids.
- Every `lv` is a pack level.
- Every level has at least one word. A level with fewer words than `setSize` produces a warning.
- Every `sentence.words` and `functionWords` id exists.
- `placement` levels exist, are in order, and fit the level's set count.
- Every placement bucket has at least 3 words. This is computed with the same set-boundary math as core.js `strata()`, and a test asserts parity via `--dump-strata`.
- `typing.strictFromLevel` exists. `typing` is an object, `"pron"` or `null`; with `"pron"`, no word having a `pron` is an error and some words lacking one is a warning.
- `tones`, when present, is `"pinyin"`. `soundsReference`, when present, is `true`; a warning when `hasLessons` is not true or no lesson row has a one-character `say`.
- Script fields: `rtl` is a bool, `langTag` is a BCP-47 tag, `fontFamily` has no `;`, `{`, `}`, `<`, `>`, `\`, `/*` or `url(`, every `fonts` entry is a Google Fonts family name, and `lineHeight` is 1–4. A pack with `rtl` true and neither `fontFamily` nor `fonts` gets a warning.
- Lesson answers are among their options.
- `passages.json`, when present: unique ids, `lv` is a pack level, `title`/`text` non-empty, non-empty `sentences` with `t`, `en` and known `words` ids, optional `spans` (a list of `[start, end, wordId]`, or `[start, end, wordId, gloss]` with a non-empty gloss string, with integer UTF-16 offsets, `0 <= start < end <= len(t)`, sorted, non-overlapping, not splitting a surrogate pair, `wordId` in that sentence's `words`, covering non-blank text), non-empty `questions` with `q`, `type` mc or tf, mc `options` of 4 distinct strings with `answer` 0–3, tf `answer` a bool and no options, known `words` ids, and `sentence` a valid index. A sentence `t` missing from `text` and a question with empty `words` are warnings.
- `pack.characters`, when present: `stages` is a non-empty list of `{after, levels}` with existing level ids, `after` non-decreasing in `pack.levels` order, and every level id covered by exactly one stage; `mastered`/`setSize` positive ints and `bare > mastered`; `learnKinds`/`reviewKinds` non-empty lists of known kinds; `testKinds`, when present, a non-empty object of known kinds to positive weights; every `stages[].levels` id at or before that stage's `after` in `pack.levels` order. `characters.json` must exist exactly when `pack.characters` does, each error naming which side is missing.
- `characters.json`, when present: unique ids, non-empty `t`, non-empty `words` with known word ids, and `lv` a pack level, equal to the level of `words[0]`, and covered by a `pack.characters.stages[].levels`. `say`, when present, is a non-empty string other than `t`; a warning when it differs from the `say` of a `words[0]` with the same text (that word's is the one spoken).
- `words[].say`, when present: a non-empty string other than `w`.
- `sentences[].spans`, when present: the `passages.json` `spans` rules without the `gloss` element (a 4-element span is an error). A linked word with no valid span in a sentence that has spans is counted into one pack-level warning (the builder's coverage metric); the summary line gains `N sentences with spans` only when some sentence has them.
- `sentences[].ruby` (and `passages.json` `sentences[].ruby`), when present: same offset rules as `passages.json` `spans` (sorted, non-overlapping, in-bounds, no split surrogate pairs, non-blank), plus a non-empty `reading` and a `wordId` that is either `null` or both in the sentence's `words` and some `characters.json` unit's `words[0]`.
- `passages.json` `titleRuby`, `questions[].ruby` and `questions[].optionsRuby` (one ruby list per option, same length as `options`), when present: the same offset and reading rules against `title`, `q` and each option, with `wordId` `null` or some `characters.json` unit's `words[0]`. Without `pack.characters` they are a warning.
- `pack.script` and `script.json`, when present: see "Script primer" above.
- Recorded audio: `pack.audio`, when present, is `{voice, version}` with a non-empty `voice` and an integer `version` ≥ 1 (other keys are a warning). `audio` on words, sentences and passage sentences is a non-empty string when present. `pack.audio` with no clip anywhere (words, sentences, passage sentences or script units), relative clips without `pack.audio`, and relative clips with no file beside the site page (resolved against the pack directory's parent, where a language repo's `index.html` sits) are warnings. `packbuilder audio --check` checks that the files exist (docs/AUDIO.md).
- `pack.legacy` and `legacy.json` must exist together, and every value in `legacy.json`'s `w`/`s`/`c` maps is a real `words.json`/`sentences.json`/`characters.json` id (duplicate values across one map are a warning).
- The generated `.js` files are in sync.

A word that shares its surface form with another word at the same level produces a warning.
