# Pack schema

A pack is one directory of JSON files that holds all the language-specific data. The engine reads nothing else.

```
<packdir>/
  pack.json        required  metadata and rules
  words.json       required  vocabulary
  sentences.json   required  example sentences (may be [])
  lessons.json     optional  "Sounds" tab lessons; required when pack.hasLessons is true
  passages.json    optional  "Read" tab graded passages with questions
  characters.json  optional  character-stage units; required when pack.characters is set
  script.json      optional  script-primer units; required when pack.script is set
  legacy.json      optional  old-app id maps for one-time progress migration
  patterns.json    optional  grammar patterns drilled as cloze; required when pack.patterns is true
  pack.js words.js sentences.js lessons.js characters.js script.js legacy.js   generated, never edit by hand
```

The `.js` files are generated with `python3 tools/jsonify_pack.py <packdir>`. They hold the same data as `const PACK=`, `WORDS=`, `SENTENCES=`, `LESSONS=`, `CHARACTERS=`, `SCRIPT=` and `LEGACY=`, so the app can load them from `file://` and `build.sh` can inline them. `passages.json` has no file of its own: its `const PASSAGES=` is appended to `sentences.js`, so `build.sh` and the dev loader need nothing new, and a pack without passages gets exactly the `sentences.js` it had before. `patterns.json` works the same way (`const PATTERNS=`, appended after `PASSAGES`). `characters.json`, `script.json` and `legacy.json` follow `lessons.json`'s pattern instead: their own optional generated file, present only when the source `.json` is. `tools/validate_pack.py` fails when they are stale.

| `typing.caseSensitive` | bool | no (false) | When false, both sides are lowercased before comparing. |
| `typing.accents` | `"lenient"` or `"strict"` | no (`"lenient"`) | With lenient, optional marks are folded on both sides: Latin accents (`perche` = `perché`), stress marks (`молоко́`), Arabic-script harakat and tatweel, Hebrew points, and ZWNJ/ZWJ (`میروم` = `می‌روم`). The digraph fold only ever runs on the target, never on what was typed, so a real "ae"/"oe" in the typed text (`Aerobic`) is never mistaken for ä/ö. Every lenient fold is guarded: an answer that matches only after folding is wrong when it is exactly another pack word (`si` for `sí`). Marks that make a different letter are kept: Cyrillic й and ї, Devanagari vowel signs, and kana voicing marks. Strict never folds them. Arabic kaf and yeh always equal their Persian/Urdu forms (ک, ی), in both modes, because keyboards produce either. |

### Lenient typing letter folds

With `typing.accents: "lenient"` (at levels before `strictFromLevel`), typed answers also fold these optional spelling variants, on both sides (core.js `LENIENT_LETTERS`, `foldLenientLetters`). Strict typing folds none of them.

| script | folds |
|---|---|
| Arabic script (ar, fa, ur) | Hamza/madda on a carrier dropped: أ إ آ → ا, ؤ → و, ئ → ی, ۓ → ے, ۂ → ہ, ۀ → ه, and a loose hamza mark (خانهٔ → خانه). ٱ ٲ ٳ ٵ → ا, ٶ ٷ → و, ٸ → ی. Standalone ء dropped. ة → ه, ۃ → ہ. ى → ی. ھ → ہ (بھائی = بہائی). |
| Devanagari (hi) | Nukta dropped (ज़ = ज, including precomposed क़–य़ U+0958–095F). Chandrabindu ँ → anusvara ं (माँ = मां). |

Not folded: a leading ال (it changes the word; `كتاب` ≠ `الكتاب` when typing), and ه vs ہ (each pack spells with one).

### German ASCII substitutions

With `typing.accents: "lenient"` and `key === "de"` (at levels before `strictFromLevel`), each target word (`w`, `alt`, and any `extra` surface) is folded a second way, on top of the plain Latin accent strip every Latin-script pack already gets: ä → ae, ö → oe, ü → ue and ß → ss (core.js `GERMAN_ASCII`, `foldGermanAscii`), gated to the German pack so no other pack's text is affected. A typed answer is accepted if it matches either folded form of any target, so a learner who drops the umlaut entirely (`mude` for `müde`, exactly as every other Latin-script pack already accepted) and one who types the digraph a German keyboard-swap convention actually uses (`Muede`, `Strasse`) are both right, and typing ä/ö/ü/ß directly still works. The digraph fold only ever runs on the target, never on the typed text itself: a real "ae"/"oe" digraph a learner actually typed (`Aerobic`) is compared as ASCII text throughout and is never turned into ä/ö by this pass, so it is never mistaken for a German word spelled with an umlaut. Because the digraph fold is additive rather than a replacement, it does not remove any collision the plain accent strip already created: `schon`/`schön` and `zahlen`/`zählen` (see the collision table below) still fold to the same key and are still caught by the same guard. An audit of `german/pack/words.json`'s `w` and `alt` fields found no *additional* pair that collides only under the digraph half of this fold (e.g. an ASCII `ss` word folding into a `ß` word the way `schon`/`schön` already collide via the plain strip); the collision guard below still covers that class generically if one is added later (proven with a synthetic `Masse`/`Maße` pair in `tests/engine_checks.js`).

**Collision guard (every lenient fold).** Folding can make distinct words one typed key: Spanish `si`/`sí`, Arabic ما "what"/ماء "water". core.js `acceptTyped` first compares strict forms (no accent or letter folding; case, whitespace, apostrophes and kaf/yeh unified as always). An exact match to the target always passes. Otherwise, in lenient mode, an answer that matches only after folding (Latin/Greek/Cyrillic accents and stress, Arabic marks, joiners, the letter folds above) is rejected when it spells another pack entry's `w` or `alt`: its strict form is that entry's, or its form without non-distinguishing marks (Arabic harakat and tatweel, Hebrew niqqud, ZWJ/ZWNJ, Cyrillic stress; core.js `pointingKey`) is that entry's and not the target's. So `مَا` or `مـا` typed for `ماء` is wrong, and so is `si` with a joiner typed for `sí`. Stress-less `замок` stays right for `за́мок` even when `замо́к` is also a pack word, because the target shares that form; typed `замо́к` is wrong. The guard needs the pack word list (`acceptTyped`'s `words` argument; the app passes `WORDS`); without it the fold alone decides. So `si` is wrong for `sí` and `ماء` for `ما`, while `perche` for `perché`, `еж` for `ёж` and `امس` for `أمس` are right. Strict mode is unchanged.

### Script display

Every element that shows target-language text carries `lang` (from `langTag`) and, when `rtl` is true, `dir="rtl"`. It also uses `fontFamily` and `lineHeight` when they are set. These elements are headwords, sentence text, word options in recall and cloze items, the cloze sentence with its blank, the typed-answer input, Words-list and teach-card rows, example sentences, reveal blocks, and lesson `rows` word cells and `say` buttons. English glosses, translations and `pron` never carry them, so they stay left-to-right; see "RTL rendering" below.

- Block elements align to their start side, which is the right in RTL. The big headword stays centred.
- Inline target text inside a mixed line, such as an option button with its number and `pron`, is wrapped in `<bdi>`, so the line never reorders. Word option buttons in RTL packs also run right-to-left, with the number on the right.
- The cloze blank `____` is bidi-isolated, so it sits where the missing word was in RTL text too.
- The Words search box uses `dir="auto"`.

#### RTL rendering

For `rtl` packs, target-language text and UI/English text never share a bidi context. Mixing them lets the bidi algorithm reorder the Latin run: `79 words` shows as `words 79`, and a gloss such as `near; (someone) has (میرے پاس: I have)` scrambles. The rules, all in engine/app.html, change nothing for LTR packs:

- **Target text** is an element with `data-tl lang dir="rtl"`: `TA`, or `tw()` for an inline `<bdi>`.
- **UI/English lines inside a target-language block** carry `dir="ltr" data-ui` (`UIA`). This includes digit-only lines. Examples are the Read-list meta line and the done tick `✓ 3 / 4` inside the RTL title button, option numbers, the `pron` beside a word option, and the weak-word reason labels. They get their own isolated LTR context and the UI font.
- **The gloss popover** (`#gloss` and the sentence token popover) is an LTR line, right-aligned in RTL packs. The word is an isolated `dir="rtl"` span, and `pron` and gloss follow as LTR runs, so a wrapping gloss never interleaves with the word. The results' weak-word rows are RTL flex rows with the checkbox on the right, where each piece is its own flex item.
- **Any UI/English string that can embed target-language text** goes through one renderer, `ui()`. That covers glosses, sentence translations, notes, lesson text, labels and the Today plan lines. It escapes the string and wraps each run of RTL script (core.js `rtlRuns`) in `<bdi data-tl lang dir="rtl" class="tlf">`, so `(bound: لـ)` keeps its order and the fragment gets the pack font. A run extends across neutrals (`...`, `…`, `/`, commas, digits, spaces) up to the last RTL letter before a Latin letter, as the Unicode bidi algorithm resolves them. So `از ... متنفرم` and `کا/کی/کے` stay one run in their own order, while `: I have)` after `میرے پاس` stays outside.
- **A pack label inside a UI line**, such as a stage label or a symbol's name, uses `tf()`. That is `ui()` for RTL packs, so a Latin name such as `choṭī he` stays UI text.
- **Inline fragments** (`.tlf`) have their line-height capped at 1, so a tall script such as Nastaliq at `lineHeight` 2.6 does not grow the UI row it sits in.

Tests check these rules on rendered markup with tests/fixtures/rtl_audit.js `rtlAudit`, from script_app_checks.js [14], engine_checks.js "RTL rendering rules on the Read screens" and characters_app_checks.js [rtl]. No UI text node, meaning Latin letters or digits without RTL letters, may have `dir="rtl"` as its nearest `dir`. RTL-script text must be inside `data-tl`, and Latin text inside `data-tl` needs a `data-ui` element in between.

**External resources.** The only external resource a built page may load is Google Fonts. The page always loads IBM Plex Sans, and it loads `pack.fonts` at runtime through a `fonts.googleapis.com/css2` URL built by core.js `fontsHref`. No other URL can come from a pack. Neither font stylesheet blocks first paint: IBM Plex is a `preload` that becomes a stylesheet once loaded, and the `pack.fonts` link starts as `media="print"` and switches to `all` on load. Text shows in the fallback stack until the webfont arrives (`display=swap`).

**Pronunciation.** `pron` is display-only. With "Show pronunciation" on (the default comes from `showPron`), a word's `pron` is shown under the headword, beside it in word options, Words-list rows and teach-card rows, and under the word in every reveal. A sentence's `pron`, such as a kana line or romanised Russian with stress marks, is shown under the sentence in read items, example sentences and reveals. It is never shown before a hear or cloze item is answered, because it would give the answer away.

**Example-sentence highlighting.** In teach cards and reveals, the taught word is bolded in each example sentence wherever it is visible. The word is found the same way as for cloze: `w`, every `alt` and every `forms` entry (core.js `textForms`), whole-word when `spaced`, overlapping hits merged into the widest one. A hit inside a longer pack word or compound is not bolded, so 本 inside 日本 is left plain. So a ja sentence with 食べた bolds it for 食べる through `forms`. When the word is not visible, as when it appears only inflected and no `alt` or `forms` entry matches, nothing is bolded. This is core.js `highlightParts`.

**Words search** matches the query against `w`, every `alt`, every `forms` entry (食べた finds 食べる), `pron` and the gloss. Both sides are lowercased and accent-folded as in lenient typing. Whitespace is also ignored, so `nihao` finds `nǐ hǎo`. A hyphen folds to a space, so a reduplicated or hyphenated lemma (`धीरे-धीरे`) matches its unhyphenated spelling (`धीरे धीरे`) too. A romanised nasal tilde (`kahā̃`) folds to a literal `n`, so plain ASCII typing (`kahan`) finds it, alongside the existing macron/dot-below folding (`ā`, `ṛ`). This is core.js `searchWords` (`searchFold`); typed-answer checking (`normalizeTyped`/`acceptTyped`) is unaffected by any of the folds below.

Arabic-script text (ar/fa/ur) has its own search folds, separate from the lenient typing letter folds above (search keeps ھ and ء, and makes ال optional): hamza and madda on a carrier drop (`انا` finds `أنا`, `سوال` finds `سؤال`), ٱ is ا, ة/ه/ۃ/ۀ all fold to ہ, ى is ی/ي (`فى` finds `في`), and a leading ال is optional on both sides (`كتاب` finds `الكتاب`). Urdu spelling variants of the same letter are unified to Urdu heh goal ہ — Arabic heh ه, teh marbuta goal ۃ, and the Arabic-preset ۀ all fold to ہ (`مدرسۃ` finds `مدرسہ`) — while do-chashmi heh ھ (a distinct aspirated phoneme) is never folded into ہ. Bari ye ے folds to ی at a word boundary only (`بڑے` and `بڑی` search as the same word); this is a deliberate tradeoff, since ے is otherwise indistinguishable from ی for search — a reveal still shows the pack's own spelling.

Devanagari text (hi) is also folded for search, the same two folds as lenient typing: nukta folds away (`जरूर` finds `ज़रूर`, `लडका` finds `लड़का`), including from a precomposed nukta letter (क़ ख़ ग़ ज़ ड़ ढ़ फ़ य़, U+0958–095F, decomposed first); chandrabindu ँ folds to anusvara ं (`हैँ` finds `हैं`), a common informal spelling swap. ZWJ/ZWNJ are dropped for every script.

## characters

Optional. A **character stage** teaches written units (hanzi, kanji-words, …) alongside the word levels, reusing the one daily new-material slot. Absent, no character code path runs, and `pack/characters.json` must not exist.

```json
"characters": {
  "label": "字",
  "stages": [ {"after":"3","levels":["1","2","3"]}, {"after":"4","levels":["4"]} ],
  "setSize": 10,
  "mastered": 3,
  "bare": 6,
  "learnKinds": ["charPick","charRead"],
  "reviewKinds": ["charRead","charSound"],
  "testKinds": {"charRead":40,"charSound":30,"charPick":30}
}
```

### bareBy

`"bareBy": "typed"` (zh only; owner feedback 2026-10-02: "writing practice should score more than selection practice", "it feels it takes more than 3/6 attempts for mastery"). A unit's streak (`prog.chars.c`) decides its tier: below `mastered` the word shows by its reading, from `mastered` written with ruby, from `bare` written alone. zh sets `bare` 5 (owner 2026-10-03, readings removed too slowly: on the owner export 347 of 353 held units reach bare in 4 weeks, against 12 at bare 6 and the 0.25 share; a stored unit at streak 5 reads as bare at the next boot, no field changes, tests/migration_checks.js [bare5]); the default stays 6. Without the flag every right unit answer (all four choice kinds) adds 1 and any miss resets to 0, and typed word answers never touch the unit.

- **Credit** (core.js `markUnitTyped`, app.html `markUnitTyped`): a right typed answer of a written-side kind on the unit's word (`written`, `writtenMeaning`, `writtenPron`; the unit is the one whose `words[0]` is the word) adds 1 to the unit, a typed miss is a unit miss (step-down below). A synonym's characters accepted for meaning -> characters (`typedSyn`) are right for the word record and its `w:` day-log entry but move no unit (neither word's), log no `c:` answer and show no dots: the learner did not write this word's characters (review 2026-10-02). Only a recorded (taught) unit moves; no record is created. The in-drill retry after a miss and the second-miss choice fallback give the unit nothing. Reading kinds (`pron`, `pronMeaning`) never touch the unit.
- **Hold** (core.js `markChar(prog, id, ok, pack, held)`): from `mastered`, a right choice answer (charRead, charSound, charPick, charRecall) counts in `r` but leaves the streak; only typed credit takes the unit from `mastered` to `bare`.
- **Miss step-down**: from `mastered`, any miss (typed or choice) steps the streak down by one, never below `mastered` (bare 5 -> 4, which shows ruby again; 4 -> 3; 3 -> 3), so the characters stay shown (fb11-miss-step; owner 2026-10-03, was a drop to `mastered`). Below `mastered` a miss resets to 0 as before. No stored field changes: the streak stays within its old range.
- **Exemption** (core.js `typedUnitWords`): a unit whose word takes no written-side kind of the pack's rotation (`typedKindOk` rejects each: shared spelling, no gloss, `noTypedMeaning`) is not held: choice answers take it to `bare` as before. On zh no unit is exempt, since meaning -> characters (`written`) needs only a written form.
- **Scheduling** (core.js `dayPlanKinds`, `typedUnitDue`; needs `dayAware`): a held unit between `mastered` and `bare` is a dayAware candidate with kinds `["type"]` and alias `w:<word id>`; when picked (the consolidating share, `DAY_TYPED_CONSOLIDATE_SHARE` 0.35 under this flag since fb10-weak-floor (was 0.25), 0.15 otherwise: ⌈0.35 n⌉ = 7 in Review, 3 in Recall (5 in a Recall of 12 under `wordsBy`), after misses and the weak-word floor), it is planned as `{ kind: "type", word, tu: unit id }` and the app picks a written-side kind of the rotation for it (`typedFromSlotItem` restricted to `TYPED_WRITTEN_KINDS`). The unit and its word are one item: `dayPick` never takes both, and a word taken first becomes the unit's typed item, except a word with a pending miss typing cannot settle: it is never converted, and gets its own item even when its unit was taken first, while a slot is left (since fb10 a typed answer settles any miss, so none is held back). Only the unit's own `c:` entry (a written-side typed answer) keeps it from repeating within `DAY_RECENT_SESSIONS`; the word's `w:` "type" (also logged for typed pinyin) does not. A typed answer settles any pending miss of the unit (core.js `daySettlesAt`). Under a `c:` key, kind `"type"` means typed from the written side only: it is logged by the app's `markUnitTyped` alone, never for a typed reading (pron, pronMeaning), so a typed reading cannot settle a unit's charRecall miss. A stepped-down unit (missed at `mastered`+) never drops to the weak tier: its pending miss puts it first (tier 0, settled by its typed item); after the miss ages out (`DAY_MISS_MAX_SESSIONS`) it comes first in the consolidating share (core.js `dayAgedOut`; the day log keeps `ag: 1` on its `c:` entry over midnight until a right answer), asked typed in the next session (tests/typed_mastery_checks.js [3]). Test Characters stays choice items. Measured by tests/day_sim_checks.js [typed week] (7 days; the check: typed only reaches bare at least as often as choice credit on the same seed): zh bare 5, units between mastered and bare at the start: 150 words / 60 units, 1 a day 16/17 (choice 12/17), 3 a day 16/17 (13/17); 595 / 300, 1 a day 34/83 (15/83), 3 a day 83/83 (49/83) (fb11-miss-step; was 36/83 with the miss drop to mastered; fb10-weak-floor; fb49c1b at bare 6, units 3-5: 16/25, 18/25, 13/120, 40/120).
- **Visible streak**: the reveal of an answer that can move the unit shows its streak as dots after the answer is marked (`字 ●●●●○○`, `aria-label` "字 4/6"; app.html `unitCue`): a first-attempt written-side typed answer, and a unit choice item unless the unit is held (at `mastered`+). Pinyin typed answers, word choice items and retries show none.
- **Storage**: no new key; one optional day-log field. Unit records keep `{r, w, s}` and their meaning; the day log gains entries `c:<id>` in kind `"type"`, a value `w:` entries already carry (an engine without the flag reads them as an unrelated kind), and `ag: 1` on a `c:` entry whose miss aged out (an engine without it drops the mark at its next midnight carry). Stored units at 3–5 wait for typed answers; units already at 6+ stay bare (tests/migration_checks.js [write]).

### bareByPair

`"bareByPair": true` (zh only; owner 2026-10-07: "a lot of words I can read without pinyin comfortably but it still shows them", then "sound too"). Needs `pack.pairs` (validator error; without it the flag reads as off). A recorded unit at the ruby tier (streak from `mastered` to below `bare`) shows bare only when BOTH its written <-> meaning pair (`wm`) AND its written <-> sound pair (`ws`) are at 2 or more right answers in a row (core.js `BARE_PAIR`, `pairBare`). Each pair is judged on its own: the unit's record (`prog.chars.c[id].p.<pair>[0]`) and its word's (`prog.w[words[0]].p.<pair>[0]`) are separate streams, and the one answered last (higher session ordinal `p.<pair>[1]`; in the same session the lower streak) decides. A miss on any of the four streams (unit wm, word wm, unit ws, word ws) sets it to 0 and the reading returns until both pairs are back at 2. Only an answered pair counts: a pair never answered reads as no answer here, not its boot from the legacy streak, which would make every mastered unit bare at once; a unit with wm at 2 and no ws answer keeps its reading. A unit below `mastered` never shows bare by this rule. The typed route (`rec.s` at `bare`, from the typed credit) is unchanged.

- **ws boost** (fb36; owner 2026-10-07, the ws pair was rarely answered so units stayed ruby; no new field): the Review plan (not Recall, Listen or Test) reserves up to 3 slots (core.js `BARE_BOOST`, `bareBoost`) for bare candidates: ruby units whose wm pair is at 2+ and whose ws pair is below 2 or never answered (`pairJudge`, as `pairBare`). They are asked in the ws direction (`pairOpts` / `pairKind`: typed written -> pron when a typed kind fits, else `charPick`), one ask per pair per session, a ws pair already answered this session is left out, a pending ws miss keeps its kind. Lowest ws streak first, then asked longest ago; the other slots follow the usual pair order. No candidate or the flag off: the plan is byte-identical to before (tests/bare_pair_checks.js [7]). Measured on the owner export, 3 Today sessions a day at 85% right: see the fb36 commit message.
- **Sites**: every display tier decision: sentence tokens (`rubyTiers`: passages, sentences, titles, questions), drill stimuli and options (`bareWord`, with `bareWords`), and the Progress characters rows when they count bare (without `freqTiers`; with it they count done).
- **Display only**: `unitDone`, goals, `progressMap`, the typed credit to `bare` (`bareBy`), the visible streak dots and scheduling read the unit streak as before.
- **Storage**: none; it reads the pair streaks `pairs` already writes (tests/migration_checks.js [bareByPair]).
- **Measured** on the owner export (a48ee4d3, which predates pairs, so no pair is answered): see the fb31 and fb35 commit messages (fb35 added the `ws` condition). Tests: tests/bare_pair_checks.js.

### withWords

`"withWords": true` (zh until fb3-lag replaced it with `learn: "lag"`, see "learn" below; review 2026-10-02: the blocking choice card put a mid-HSK 2 learner on 15 character sets in a row, and Skip deferred every character to after HSK 4). No choice card. Whenever a characters stage is unlocked (its `after` level's words learned) and not finished, and words remain to learn, Today's Learn takes turns: `chars.turn` (`"c"` or `"w"`) names the kind the next Learn teaches, the oldest such stage's next set (10 units) or the next word set (core.js `nextStage`). It flips when a Learn step completes (core.js `learnTurnDone`, from app.html `todayLearnDone` / `todayCharsDone`), so a learner who closes Today right after Learn still alternates (review 2026-10-02: turning on finished sessions taught one kind only). Without the field, `prog.sessions` parity (odd characters, even words). A session closed before its Learn completes keeps the turn; a resumed session teaches what its snapshot planned. |---|---|---|---|

Under `pronFirst`, a word still shown by its reading never gets a kind that shows or asks for its characters (written, writtenMeaning, writtenPron), exactly as the written item already fell back. A word no kind fits gets the recall item.
- **Meaning -> characters** (`written`, app.html `silentWrittenTypeItem`): under `typedFrom` the card is silent before the answer: no audio on mount, no Replay, kind tag "characters" without "listen". - **Stimulus rules** (app.html `stimWritten`, `stimPron`): the card plays nothing before the answer and has no Replay button. Characters carry no reading, ruby or tone colours. The reveal plays the word's audio and shows Replay, as other typed items do.
- **Checking**: a typed reading uses `checkPronTyped` (tones optional, "tones:" note). A typed meaning uses `checkGlossTyped`, below. Input is Latin (`lang="en"`).
- **Misses**: every kind records under `w:<id>` with miss kind `k: "type"`, as today (`applyMissedKinds`, `dropBadMissKinds` unchanged). No new progress field, so the storage shape is unchanged.
- **Test tab**: the Test recall drill builds its items the same way, so the new kinds appear there too. Placement is unchanged.

**Typed meaning** (core.js `checkGlossTyped(val, en)`): one meaning is enough. The gloss is split into alternatives on `;` and on `,` outside brackets. The typed text is accepted when it matches one alternative, or when each of its own `;`/`,` parts does. Both sides are compared as keys (`glossKey`):

1. Unicode NFKD, combining marks removed (`cafe` = `café`), lowercased.
2. `.` and apostrophes removed without a space (`oclock` = `o'clock`, `eg` = `e.g.`); `...` and `…` vanish this way or in step 3.
3. Every other non-letter, non-digit run becomes a word break (hyphens, slashes, brackets, `!`).
4. The words `a`, `an`, `the`, `sb`, `sth`, `someone`, `somebody`, `something`, `etc` and `eg` are dropped, unless that would leave nothing.
5. A leading `to` is dropped when more words follow (`kick` = `to kick`).
6. The words are joined with no spaces, so spacing never matters.

Each `(...)` group in an alternative is optional: the alternative is keyed with every combination of its groups kept (brackets removed) or left out, up to four groups (later groups always kept). So for "to kick; to play (e.g. soccer)", `kick`, `to play`, `play soccer` and `to play (e.g. soccer)` are right and `soccer` is wrong.

Six more rules keep a typed meaning a real meaning (core.js `glossAltKeys`; tests/typed_from_checks.js [2]):

1. **Reading notes are never meanings.** An alternative or `(...)` group matching `PR_NOTE` (`also pr. [shuí]`, `(colloquial pr. [nèi])`, `colloquial pr. [xiě]`) or a bare `[...]` alternative is a note (core.js `isPronNote`). It is left out of the keys, so `also pr shui` is wrong for 谁. `glossParts` returns it in `notes`: stimuli, options and Words rows never show it (it spells a reading), and the reveal and the word popover append it dimmed, after the answer.
2. **A truncated fragment is not a meaning.** An alternative ending in `…` or `...` whose words are all function words (`to`, `be`, `is`, `are`, `of`, `and`, `or`, `that`, the dropped words of step 4 above, and a few more forms of "be") is skipped: `to` is wrong for 相信 ("…; to believe; to…"), `be` and `to be` for 只好. A truncated alternative with a content word counts (`with` for 和, `him` for 他).
3. **A lone letter left by punctuation is not a meaning.** A key of one letter counts only when the alternative is that letter as written: `i` is right for "I; me; my", `s` is wrong for 的 ("~'s").
4. **"A or B":** the text before an alternative's first top-level ` or ` also counts when exactly one word follows the ` or ` (`(...)` groups aside) and the left side has a content word (same list as rule 2): `no matter what` for "no matter what or how", `we` for "we or us…", `in confusion` for "in confusion or disorder", `hang` for "to hang or suspend (from a hook etc)". A longer right side shares its tail with the left, so nothing splits: `hot` is wrong for "hot or boiling water", `give` for "to give or have an injection", `go on official` for "to go on an official or business trip". The text after ` or ` alone never counts (`how`, `us`, `disorder` are wrong).
5. **Display of qualifiers** (glossFocus, `glossParts(en).pieces`): see below.
6. **Copula** (core.js `copulaFree`; typed-meaning packs only: `glossAltKeys(en, pack)` / `checkGlossTyped(val, en, pack)` apply it when `typedFromOn(pack)`, every other pack keeps its keys): an alternative "to be X" or "to feel X" also keys X when X is one word, an adjective or participle: `careful` for "to be careful", `anxious` for 着急 "to feel anxious", `born` for "to be born". A preposition, adverb or function word (`like`, `apart`, `away`, `over`, `left`, `able`, `there` …; `GLOSS_COPULA_NOT`) or more than one word after the copula keys nothing: "to be like", "to be apart from", "to be able to", "to be (followed by substantives only)", "to feel that ...". A learner names the quality, not the copula (owner feedback 2026-10-02).

**`glossFocus`** (core.js `glossParts(en)` → `{primary, qualifiers, notes, pieces}`; app.html `glossOut`): each top-level `(...)` group is dimmed (`<span class="dim">`) and stays inside its own alternative (the `;`/`,`-parts). A group that opens its alternative moves to the end of that alternative; any other group stays where it is. So "(of a contagious disease etc) to spread; to propagate" shows as "to spread <dim>(of a contagious disease etc)</dim>; to propagate", "just at (that time); right in (that place)" and "to be (located) at" keep their groups in place. Reading notes (rule 1 above) are removed; `glossOut(s, true)` (reveal, popover) appends them dimmed. `primary` is the text without groups or notes. A gloss that is nothing but groups, "(completed action marker)", and an unclosed "(" stay as written. It applies wherever a word gloss is rendered: drill stimuli and reveals, meaning options (hear, read, placement, charRead), character items and teach cards, Words and Progress rows, and the word popover. A passage span's own display gloss (`gloss_display.json`) is shown as written. Answer checking always compares the raw gloss.

Validation: tools/validate_pack.py does not check these two fields yet.

### Synonyms

Four optional words.json fields, generated at pack build (zh: tools/zh_gloss.js, run by tools/pack_from_hsk.py; report docs/ZH_GLOSS.md). A pack without them plans and renders as before: every rule below reads only these fields (tests/gloss_overlap_checks.js flag-off cases; tests/flagoff_snapshot.js strips them). Owner feedback 2026-10-02: 着急 "to worry; to feel anxious" and 担心 "anxious; worried" could be each other's distractor, so a right pick was marked wrong.

- **`syn`** (`[id]`, symmetric): the words share an accepted meaning. Generated: a `glossAltKeys(en, pack)` key (the key the typed-meaning matcher compares, explanatory alternatives included: 吧 "...right?" and 右边 "right" are syn) shared by both glosses, plus each pair of a reviewed group (tools/zh_gloss_overrides.json `synonyms`) for synonyms the keys miss (worry / worried), plus every `typedSyn` pair. A syn is never a wrong option for the other word (core.js `isSyn`): meaning options (`meaningOpts`: read, hear, placement, the meaning choice fallback, character `charRead` via `charReadOpts`), word options (`wordOpts`: recall in both label modes, cloze `gapChoices`) and character picks (`charOpts`: charRecall, charPick). Homonyms count ("lamp; light" and "light; easy" share `light`): a shown option "lamp; light" fits "What does 轻 mean?". A key that exists only because of folding is a collision, not a homonym, and is fixed in the gloss (上午 "a.m." folded to `am`, the key of 是 "am", so it was dropped). A key that exists only because of folding is not a homonym: zh's reviewed `notSyn` entries (`{key, sets: [[words], [words]], why}`) keep words in different sets from being linked by that key (上午 "a.m." folds to `am`, the key of 是 "am"); the build fails when an entry names no such shared-key group.
- **`typedSyn`** (`[id]`, directed, within `syn`): typing the other word on this word's meaning stimulus is right. Generated: the other word's keys (register labels such as "(coll.)" ignored, unless a label is all that tells the two glosses apart: 你 "you (informal)" / 您 "you (courteous)" stay apart, 爸爸 "(coll.) father; dad" / 父亲 "father" do not) include a key of this gloss's first alternative, the meaning a learner names first (但是 "but; however" takes 可是, 却, 不过, 然而; 词典 "dictionary" takes 字典). A reviewed `synonyms` group adds typedSyn only with `"typed": true` (truly interchangeable: 着急/担心/烦恼, 突然/忽然, 一定/肯定, 可能/也许); a group without it is syn only (可能/大概, 容易/简单). The accepted and rejected lists are printed in docs/ZH_GLOSS.md. A typed item whose stimulus is the meaning accepts a typedSyn word's answer as right and the reveal names it (its first alternative only: "also right: dānxīn · anxious"; app.html `synTyped`, core.js `typedSynHit`): meaning -> reading (`pronTypeItem`), meaning -> characters (`writtenTypeItem`, `silentWrittenTypeItem`), meaning -> word (`typeItem`). The item still records the asked word. A characters stimulus (`writtenPronTypeItem`) never takes a synonym. A shared homonym is not a typedSyn: the rest of "lamp; light" tells 灯 from 轻. Typed cloze (`gapType`) is not covered: its sentence is the disambiguating stimulus, and a typing `"pron"` pack never gets it.

### pronFirst

`"pronFirst": true` (zh and ja) makes a logographic pack pronunciation-first: the learner never starts from the written form. A word whose character unit is below the `mastered` tier is shown by its `pron` (pinyin, kana) wherever its written form would otherwise appear. That covers teach rows, every word drill (stimulus, options, reveal), the Words list and search, Test, Progress and result screens, and the Read tab's tap spans and popover. The unit is the one whose `words[0]` is the word. A word with no unit (a kana word) or no `pron` is shown as written. Once the unit is mastered the word is shown written, with its `pron` beside it as usual (with `characters.bareWords`, not on a drill question once the unit is bare). The written form is taught only in the characters stage (teach cards and the four unit item kinds), which is unchanged.

Sentences follow the same rule token by token (`ruby`): before characters start, or with the mix preference off, every token shows its reading. Once they have started with mix on, a token below mastered shows its reading, and the ruby and bare tiers apply from mastered. With Latin readings, tokens are spaced and full-width punctuation is shown in ASCII form. These spacing rules are display cosmetics keyed on Unicode script (Latin readings get spaces, Han text outside tokens triggers the reading-line fallback). They never affect scoring or which tier a token gets. A sentence whose written characters are not all inside `ruby` tokens (a name, a word with no unit) is shown by its sentence `pron` instead, and is never used as a cloze item. "Show pronunciation" off hides only the ruby over written tokens. The reading itself is always shown. The bare hide (`ruby.bare rt{visibility:hidden}`, a global rule keeping the `<rt>` width) applies at every ruby site alike: passage body, question stem, option, title, list button and results.

A small **show written** tap sits beside every word or sentence shown by its reading (never inside answer buttons or passage tap spans, which are tap targets themselves). It swaps itself for the written form, for that item only, with no progress effect, so a learner who wants the characters is never blocked. Keys pressed on it never reach the drill shortcuts. When it had keyboard focus, the revealed text takes the focus. Its label is left out of the live-region announcement.

In the characters stage, a unit's teach card shows its example sentence with that unit's own tokens written, with ruby. The other tokens follow the rule above. The example is picked by core.js `unitExampleSentences`: first a sentence with a `ruby` token of the unit's word whose tokens cover every Han character (core.js `rubyCovers`, the same test that decides the reading-line fallback), then one with the unit's token, then any other. So the card shows the unit written whenever some sentence of its word allows it.

Recall and cloze options are unambiguous when shown by their readings: no two options sound alike, and no two share a written form. Recall options are keyed by word id. A distractor with the same `pron` as the answer or another option, or written as another option's reading, is dropped. This is core.js `pronClash` in `wordOpts`.

The rules live in core.js: `displayForm(word, units, prog, pack)` returns `{text, isPron, written}`, plus `sentenceDisplay`, `sentencePieces`, `rubyTiers` and `pronFirstOn`. Validation: `pronFirst` must be a boolean.

A passage span can be longer than its linked word: 这个 links 这, 越来越 links 越, 一下 links 下. Without `ruby`, such a span reads as core.js `composeSpanReading`. Each place the word's written form occurs gets the word's `pron`. With `characters.compose`, every other character gets the reading of the single-character unit with that `t` (the first in file order). Without it, every other character stays written: a character's reading can depend on its word (ja 時 is じ in 6時, とき alone), so no reading is guessed. A character with no reading stays written, so a span never loses a character. The popover of such a span shows the tapped surface with that reading as its headword, and show written gives the surface. A span equal to its word keeps the word's own headword. A reading that starts a sentence is capitalised, including one after a sentence-internal `.`, `!` or `?` and the first inside a quote opened after a colon. An ellipsis stays as written and starts nothing.

### dayAware

`"dayAware": true` (zh only for now; owner feedback 2026-10-02: "if I finish many sessions a day many drills are repeated and many important recalls are not given"). Without it every planner ranks by `weakScore` (3 × lifetime misses − streak), which knows neither today nor time: each session drilled the same lifetime-weak units, a unit missed today could miss the next plans, and a mastered unit was never refreshed. Measured on zh by tests/day_sim_checks.js (8 Today sessions, one day, 85% right): session 8 had 61–65% of items in a kind already answered right that day; flag on, 0%.

**Storage (additive; only written with the flag).**
- `prog.day = { d, n, a }`: today's log. `d` the local date `YYYY-MM-DD`; `n` the drill ordinal (each drill started today, +1); `a[key]` per item key (`w:<word id>`, `c:<unit id>`, `s:<sentence id>`, `x:<script unit id>`) `{ r?: [kinds answered right], c?: n of the last right answer today, m?: n of the last miss today, mk?: [missed kinds not yet settled], ms?: prog.sn of the first of those misses, ma?: 1 once the item was asked again while they were pending, u?: prog.sn of the last right answer }`. A log from another date reads as a new day that carries over, per key, only the unsettled misses (`{mk, ms?, ma?}`, until settled or aged out, see Kinds) and the right kinds of the last `DAY_RECENT_SESSIONS` (2) sessions (`{r, u}`); a malformed log reads as a fresh day. The log is never validated at boot, so it can never send the progress record to backup. A cloze answer also logs the blanked word with kind `gap`; a right cloze neither counts as the word answered right nor settles its miss, and leaves the word record's `t`/`u`.
- `prog.sn`: the session ordinal, the planner's clock (owner 2026-10-02: "count by sessions rather than days"). +1 when Start today is tapped and for every drill started outside Today that drills words, sentences, character or script units (Test, Words-tab review or set drill, script practice); a drill of no unit (Sounds lessons), Today's own step drills and a resumed session never count. Missing or malformed reads as 0.
- `t` on `prog.w`, `prog.s`, `prog.chars.c` and `prog.script.u` records: day number (days since 1970-01-01, local date) of the last answer; `u`: `prog.sn` at the last answer. Missing on older records, which then rank as the longest unseen.
- `f` on `prog.w` and `prog.chars.c` records (optional number, only under `optsMix`, see "optsMix"): `prog.sn` when the record was created, i.e. the session the word or unit was learned in. Written once on a record made by an answer (Learn, a drill, a review), never on placement `prov`, Read `d` or older records, never changed; absent flag-off. `validateRecMap` requires a number.
- None changes the meaning of any existing field; an engine without the flag keeps them all and ignores them (the engine before dayAware, 3d66aea, boots such progress with no backup: tests/migration_checks.js [day]).

**Kinds.** One partition for words, sentences and character units: production is recall, type (every typed variant), gap, gapType, charRecall, charPick; recognition is hear, read, charRead, charSound (core.js `DAY_PRODUCTION`). A miss stays in `mk`, across days, until a right answer in a later drill settles it: one in the missed kind, or in any production kind (a production answer settles a recognition miss too: owner 2026-10-03, a word missed by ear got no production ask for the rest of the week in 89% of cases). An easier kind never settles a miss (a recall miss answered right by ear stays pending), and neither does the in-drill retry. A missed kind the unit cannot be shown in on this device (hear with no voice or recorded audio, a cloze with no blankable word) counts as the nearest kind it can be shown in: the first renderable kind of the same partition, else the first renderable kind (core.js `dayMissKinds`, beside `daySettles`); planners only ask a unit in kinds it can be shown in (`dayWordCan`, `daySentenceCan`), and the logged kind is the one shown. Safety net: a miss asked again at least once (`ma`) and still pending `DAY_MISS_MAX_SESSIONS` (6) sessions after its first miss (`ms`) is dropped; the broken streak keeps the unit weak.

**Planning (core.js `dayPick`, `dayItemKind`).** Every candidate gets a tier: 0 missed (today or any earlier day), not yet settled, and this planner can ask a kind that settles it; 1 due: below the mastered streak and not right recently; 2 mastered and not right recently; 3 right recently, with a kind this planner asks still open; 4 right recently in every kind it asks, or a pending miss this planner cannot settle (a recall miss in Listen or Test Sentences by ear). A plan of n takes tier 0 (pending longest first, by `ms`, then weakest) up to ⌊0.6 n⌋ (`DAY_MISS_SHARE`, at least 1; the rest stay pending and fill only after tier 3), then the weak-word floor: words (keys `w:`, never units or sentences) of tier 1 (lowest streak, then longest unseen) until round(n × `DAY_WEAK_FLOOR` 0.4) of the plan are words, word misses already taken counting, and never into the last ⌈0.15 n⌉ slots while consolidating units are waiting (8 of 20 in Review, 3 of 8 in Recall (5 of 12 under `wordsBy`), 5 of 12 in Listen; owner 2026-10-03: weak words had lost their slots to unit misses, consolidation and refresh, 0.5 of 8 in Recall). "Right recently" is right today or in the last `DAY_RECENT_SESSIONS` (2) sessions (core.js; one constant), so the first session after midnight does not replay the evening's items. "Longest unseen" is fewest sessions since the last answer (`u`), then the oldest day (`t`). Then up to ⌈0.15 n⌉ consolidating character units (tier 2 with a streak below `bare`, longest unseen first: by weakScore alone a unit at streak 3–5 had no Review/Recall slot at all), then up to ⌈0.2 n⌉ of tier 2 (longest unseen first), then tier 1 (lowest streak, then longest unseen), then up to ⌈0.25 n⌉ of tier 3, then the rest of the consolidating units and of tier 2, the rest of tier 3, and tier 4 only when nothing else is left. The in-drill retry after a miss does not count as right for its kind, so the missed kind stays open. `dayItemKind` is the one place a unit's kind is decided for the day: a pending miss goes to a kind that settles it (the planned kind if it does, else its missed kind, else the nearest production kind, preferring one that settles every pending kind, so a hear and a recall miss go to recall, then one not right today); a unit already right today is asked in an open kind, production first. With the flag, the Today plan lines read "misses and due first" instead of "weakest first". Kinds and plan sizes otherwise come from the unchanged builders (kindMix, applyMissedKinds, hearableKinds).

**Sites.** Today Review, Listen, Recall and Sentences; Test Listen, Recall, Sentences and Characters; Words-tab review; the script practice drill. Unchanged: Learn (new words, new character sets: new material keeps its pace every session), the Words-tab set drill (the learner picked the set), lessons, placement, passages (already spaced by day), the Progress weak list (display only). Validation: `dayAware` must be a boolean. Ties are jittered by the caller's random source, so a plan is a function of (progress incl. the day log, date, draws); session resume records the drawn items as before.

### wordsBy

A word is known (`WORD_MASTERED` 3: Progress counts, the mastered planner tier, `prov`) by its streak in `prog.w`. Without the flag any right answer adds 1 and any miss resets to 0.

- **Credit and hold** (core.js `markWordRec`, used by app.html `markWord`): below `WORD_HOLD` (2) unchanged. From 2, a right answer in kind `"type"` adds 1; a right choice or ear answer (recall, read, hear, and the choice fallback after a typed miss) counts in `r` and leaves the streak, so a word becomes known only by a typed answer at 2. Kind `"type"` is every typed word item: characters (`written`, typed from the meaning), the reading (`pron`, typed pinyin: owner's "writing" covers it), the meaning (`writtenMeaning`, `pronMeaning`), the reading from the characters (`writtenPron`), and `word` on packs without pron typing. A missed retry counts in `w` and leaves the streak too (3 → 2 on the miss, still 2 after a second miss in the drill). The drill records which words a miss stepped down from 2+ (app.html `wordRetry`, `D.down`; kept in the drill record as `dn`, so a reload between the miss and the retry changes nothing). A word missed below 2 keeps the old retry: a new word missed once in a Learn pair (hear + read) still ends Learn at 2 (review 2 M1), and a right answer in a later drill of the session counts as usual. A word not typed this session is never downgraded. The in-drill requeue after a typed miss stays typed and earns no streak (practice only; see "Miss step-down"); the Recall replay of the miss is a choice kind (recall). ### pairs

Needs `dayAware` (validator error; without it the flag reads as off). Allowed with `script` since port E3 (script units have no pairs; see Script units below). ### freqTiers

`"freqTiers": true` (zh only; owner 2026-10-06: "Should we give more priority to words that come up more in real life and the exam? Not just word order, mastery requirements as well.", then "why not typed asks but much less frequent?"). Needs `pairs` (validator error; core.js `freqTiersOn` reads it as off without `pairs`). Every word carries `ft`: 0 ambient (我 你 是 的 了 不: every sentence rehearses them), 1 core (虽然), 2 peripheral (爬山). Pair and unit mechanics are the same in every tier (pair 2 → 3 by production, typed included; a unit mastered → bare by typed credit only, `bareBy` "typed"). The tiers differ in how often an item is asked and in the known bar:

### optsMix

`"optsMix": true` (zh only; owner 2026-10-02: "near the end of an hsk level, i can guess new words in drill by deducting which words must not be it ... Why not random pick?"). Off, every option builder keeps its level tiers (same level first) and draws exactly as before (tests/opts_mix_checks.js [3], control vs main 68930bd). A first version mixed learned and not-yet-learned options 1+2 / 2+1; review measured that a learner who rules out the other familiarity class still guesses right 40% of the time, so wrong choices now come from the answer's own stage.

- **Stages** (app.html `wordMix` / `sentMix` / `charCtx` pass a `stage` function; core.js stays pure):

Each group is shuffled; no level ordering. The old strict / non-strict passes take the first 3.

Bucket 0: same `f`. Bucket 1: the adjacent learn session, counted over the distinct `f` values among word and unit records (so review sessions between two Learn sessions do not count). Bucket 2: the rest. While a Learn drill is built (`withLearn`) its words and units have no record yet and count as learned in the current session. A record without `f` predates every stamped record: adjacent (1) to the earliest stamped session, else 2.
  - **Positional fallback**, only when neither record has `f` (older progress, placement `prov`, Read `d`): word set = position in its level's list over `setSize`, counted on through the levels in order; unit set = position in the stage order (`charStageUnits`) over `characters.setSize`. Same session, same answer, same set; the number over a week fell to 2–4%.

### Pronunciation aids

Three pack fields and the sentence `ruby` turn on learning aids for the reading. Each is off unless the pack sets it, so every other pack renders exactly as before (tests/pron_aids_checks.js [7], tests/flagoff_snapshot.js).

- **Word taps in sentences** (a sentence drawn with its `ruby` tokens: always under `pronFirst`, and on a word-first characters pack once characters have started with mix on; also passage question reveals and results under `pronFirst`): each token with a known word is a tap target (Enter or Space from the keyboard). A tap shows the word's popover, the same one the Read tab uses (reading, gloss, show written), inside that sentence, and speaks the word only. A token whose surface contains its word and more (这个 for 这, 他们 for 他) is a phrase token: its popover heads with the surface's reading, show written gives the surface, and the tap speaks the surface. A token covering only part of its word (ja ruby over the written stem) keeps the word's headword. Escape closes any open popover or Read-tab gloss box and clears the tapped highlight, staying on the same view (inside a drill it does not quit); with nothing open it works as usual. The sentence itself is heard from its own speaker button, not by tapping the text. Question stimuli and answer options never carry taps. A tap has no progress effect. Sentence rows, reveal blocks, teach examples and passage reveals get taps; a sentence shown by its sentence `pron` line has no tokens and keeps the old whole-row tap.
- **`tones: "pinyin"`**: every displayed reading is coloured per syllable, as `<span class="t1">` to `t5` (tone 1 to 4, 5 for neutral), with light and dark colours. This covers word displays, sentence tokens and ruby, options, reveals, the Words list, popovers, teach rows, character items and lesson rows. A reading is split into syllables by the tone marks on its vowels and the pinyin syllable inventory (core.js `splitReading`, `splitSyllable`, `markSyllable`, `toneHTML`). A letter run that does not split into syllables (a Latin name, "OK") stays uncoloured.
- **`typing: "pron"`**: the production slot that alternates with recall (the same rule as other typing packs) is one of two typed items. The plan is unchanged. The item is picked by the slot's order among the plan's "type" slots: the first, third and later odd slots type the reading, the rest type the characters (core.js `typeSlotKind`, no randomness, so plans stay reproducible). Each card has a kind tag, its own heading and its own placeholder. A pack with `typedFrom` replaces this alternation with the rotation in "typedFrom and glossFocus" below.
  - **Type the pinyin** (the reading; "Type the reading" when `tones` is unset): the card shows the meaning and plays no audio before the answer, since audio would give the reading away. The input is a Latin one (`lang="en"`). Tones are optional. Tone marks or tone numbers are accepted; a neutral syllable may be written 5, 0 or with no digit, and an r-suffixed syllable with its digit after the r, or before it with the r bare, r5 or r0 (hsk's `yi1hui4r5`). Case, spaces and apostrophes are ignored, and v or u: stand for ü. The right letters with no tones, or with other tones, also count as right, and a "tones:" note gives the tone-coloured marked form. Other letters are wrong. This is core.js `checkPronTyped` ("ok", "tones", "tonesDiff", "wrong").
  - **Without `tones`** (ja: kana readings): "Type the reading", tag "reading", placeholder "reading…", and no tone note. The input takes the target-language attributes when the reading is not Latin script, so the kana keyboard comes up. The typed reading must equal the `pron` after `plainPronKey`: NFKC (half-width kana count as full width), katakana folded to hiragana on both sides (テレビ may be typed てれび and the reverse), then `normalizeTyped`, and letters, marks and digits are kept; everything else removed (spaces, the affix mark 〜, the middle dot ・), then NFC recomposed (a standalone voicing mark ゛ typed after its kana, は゛す, recomposes to ばす, matching バス). The long-vowel mark ー, small kana and voicing marks must match exactly: こうひい is not コーヒー, きやく is not きゃく. The verdict is "ok" or "wrong" only; pinyin syllable splitting and tone digits never apply (たべる1 is wrong).
  - **Type the characters**: the card shows the meaning, plays the word's audio once and has a replay button (as hear items). With `typedFrom` it is silent until answered (see "typedFrom and glossFocus"). The input carries the target-language attributes, so a phone keyboard switches to the pack's language. The written form or any `alt` is accepted (core.js `acceptTyped` with default options), and so are its affix-bare/slash-alternative forms (core.js `affixAlts`; see the `typing` row above). Katakana and hiragana are not interchangeable here: the written form is the spelling (テレビ). Without `tones` (a Latin reading excepted) the typed value is also NFKC-folded with ～ unified to 〜 before comparison (core.js `writtenTypedFold`), so half-width kana (ﾃﾚﾋﾞ) matches full-width (テレビ) and either affix-mark tilde matches whichever the written form uses.
  - The characters item needs the word's written form on display. Under `pronFirst`, a word below its character tier is shown by its reading only, so the learner has not seen its characters; that word gets the pinyin item in both slots, and the alternation resumes once the word reaches its tier. A word with no `pron` always gets the characters item. Both items record progress under the same `w:<id>` key as every other word item. The reading is never drilled on its own, typed cloze items never appear (the blank is written), and placement is unchanged.
- **`soundsReference: true`**: a collapsed Reference card below the Sounds lesson list. It lists every lesson row whose `say` is one character (its reading coloured, each reading once), grouped by lesson. Tapping a cell speaks that character. The zh lessons already cover every initial, final and tone, so the card is built from them, not from a separate chart file.

## pack/characters.json

Required when `pack.characters` is set (and must be absent otherwise). Holds the units, in teaching order within each level: sets are consecutive runs of `setSize` units of one level, in file order.

`[{ id, t, words, lv, ft?, reading?, hint?, say? }]`

| field | type | meaning |
|---|---|---|
| `id` | `c0001`…, unique | Progress key. Builders derive it from the unit's `words[0]` id (`w0416` → `c0416`), so ids follow word ids and are never renumbered when units are added or left out; a pack with gaps in unit ids is normal. |
| `t` | non-empty string | Written form, shown large. |
| `words` | `[wordId]`, non-empty | Linked words, ids from this pack's `words.json`. `words[0]` supplies the gloss and the audio. |
| `lv` | levelId | Must be one of `pack.levels[].id`, equal to the `lv` of `words[0]`, and covered by one of `pack.characters.stages[].levels` — decides which stage the unit belongs to. |
| `ft` | 0, 1 or 2 | Optional unit frequency tier, the lowest `ft` of its words (validator checks it). Read only under `pack.freqTiers`; see "freqTiers". |
| `reading` | string | Optional. Answer for `charSound` and the ruby text. Defaults to the `pron` of `words[0]`. |
| `hint` | `[string \| null]` | Optional. A memory hint per character of `t` (aligned by code point, `null` for a character without one; at least one string, else leave the field out). The generator decides what an entry says; zh: a one-character unit gets a component breakdown ("a woman 女 with a son 子: good"), a unit of two or more characters gets only each character's own meaning (`我们` -> `I`, `(plural)`, shown as "我 I" / "们 (plural)"), with no components (owner 2026-10-07), so every unit has a hint (1193 of 1193). Shown dimmed under the form on the teach card and in every unit item's reveal, one line per distinct character, prefixed with the character when `t` has more than one; a character already hinted with the same text on the same teach screen is not repeated, while the same character in another sense is (衣服 "服 clothes" then 服务员 "服 to serve"; key character + hint text, core.js `hintKey` / `unitHints`, app.html `charHintHTML`; a pack whose characters carry one hint text each dedupes exactly as by character). Under `pack.tones` a marked pinyin syllable inside a hint ("sound cǐ") takes the same per-syllable tone classes as word pinyin (`toneHTML`); unmarked text is unchanged (fb21). The word popover (a tapped sentence token or Read-tab word) shows the hints of the word's unit (`words[0]`) after the gloss, the same way, only while the word is shown written: under `pronFirst` a hint's characters would spell a form not yet taught. Results weak-word rows do not. Never on a stimulus or option: a hint names the meaning and parts, so it would answer charRead/charSound/charPick. Absent, nothing renders (byte-identical). zh: `tools/pack_from_hsk.py` from the committed tools/zh_hints.json (tools/zh_hints.py over Make Me a Hanzi, LGPL-3.0-or-later, credited in packs/zh/attribution.json; hand overrides in tools/zh_hints_overrides.json, no entry cap: 24 of its 37 are source gaps; per-character meanings for multi-character units in tools/zh_hint_meanings.json from the same script, `_meanings` overrides in the overrides file). A character's meaning is the sense it has in that word (owner 2026-10-07: 便宜 is not "便 easy, 宜 fitting"): a `_meanings` key is either a character (the default for every compound) or `compound:char` (that compound only, e.g. `服务员:服` "to serve" beside `衣服:服` "clothes"), which wins; a suffix or particle is labelled as one ("儿 (suffix)", "子 (noun suffix)", "们 (plural)"), a bound morpheme as "(part of 钥匙 key)" or "(with 烦: trouble)", a transliteration as "(sound qiǎo)". All 830 multi-character units were reviewed by hand (fb33): 723 overrides, 1702 character lines of which 753 differ from the plain first sense. `pack_from_hsk.attach_hints` fails on a compound key no unit has; `zh_hints.py` fails on a key whose char is not in its compound. |
| `say` | string | Optional TTS carrier, as words.json `say`. A unit is spoken through `words[0]` (whose `say` then applies), so the unit's own `say` is heard only for a unit with no word; packs/zh copies the word's. Never displayed. |

`tools/validate_pack.py` checks unique ids, that every `words` id exists, and that `lv` is a pack level, equals the level of `words[0]`, and is covered by a stage; a `hint` must be a list of non-empty strings or null, one per character of `t`, not all null.

| `tts` | bool | no (true) | `false` treats every `say` as absent: `soundSym` shows the `roman` as text and `wordHear` becomes `wordRead`. A unit's recorded `audio` still plays. |
| `learnKinds` | kinds, non-empty | no (`symSound`, `soundSym`) | One Learn item per kind per unit, among the kinds the unit can carry (below). |
| `reviewKinds` | kinds, non-empty | no (`symSound`, `soundSym`, `wordRead`) | Review draws one at random per unit. |
| `testKinds` | `{kind: weight}` | no (`symSound` 35, `soundSym` 25, `wordRead` 25, `symType` 15) | The Script tab's practice mix. |

Kinds are `symSound`, `soundSym`, `symType`, `compose`, `formFind`, `formMatch`, `wordRead`, `wordHear` (`docs/SCRIPT_PRIMER.md` §2). A unit carries a kind only when it has what the kind needs: the three sound kinds need `sound` not false; `compose` needs `syll`; `formMatch` needs `joins`; `formFind`, `wordRead` and `wordHear` need `ex`. A `sound:false` unit gets `wordRead` in place of the sound kinds in Learn. An option kind also needs at least 4 distinct options drawn from all the pack's units, or it is never asked of that unit.

`notes`: `[{st, set, h, body}]`, rule cards shown with the teach cards of that stage's set. `h` and `body` are plain text (escaped).

**Example words** are shown in the script being taught: a word whose `w` uses letters outside the primer's units while its `pron` is written entirely with them (ja kanji words) is shown, spoken and answered by its `pron`; otherwise by its `w`.

**Pairs.** With `pairs` (and `dayAware`), Review keeps the script units the Review without pairs would ask, in their review kinds; script units have no pairs and no `p` ("pairs", Script units).

**Progress.** `prog.script = {v:1, u:{[unitId]:{r,w,s}}, skipped, skip:{[stageKey]:bool}, choiceSeen, notice}`, present only with `pack.script`. `skipped` turns the whole primer off and `skip` one stage; an off stage leaves the path, Review and Test, and its records are kept. Taught, done and mastered are derived: a set is taught and a stage done once every unit has a record; mastered is streak ≥ `mastered`. Stored progress with word records and no `script` field (a learner from before the primer) normalizes to `skipped:true, choiceSeen:true, notice:true`: the primer starts off, with a one-time notice that it can be turned on in Progress. Fresh progress starts with the primer on and the choice card unanswered. Turning the primer or a stage on in Progress clears `notice`. `prog.script` is created whenever `pack.script` is set, even when `script.js` has no units and the primer is off; it is then inert.

**Validation** (`tools/validate_pack.py`): `script.json` exists exactly when `pack.script` does; `pack.script` field types and known kinds; unit ids unique and well-formed; `st` a stage key, `set` an int ≥ 1, each stage's sets contiguous from 1, every stage non-empty; `t` and `roman` non-empty, `sound` a bool, `alt` strings; `confuse` and `base` known ids; `ex` word ids exist, from the first or second level (the second is a warning; a unit of a later stage may also use the third level, with a warning, because a later stage such as ja katakana teaches a script the first levels barely use), the roman non-empty and the glyph in the word (compared after compatibility decomposition and lower-casing, with positional letter variants folded); `syll.parts` glyphs of units at or before the set and `syll.t` in a first-level word (for a later stage, after folding katakana to hiragana); `joins` only in an `rtl` pack; `notes` on a known stage set. Warnings: a unit with no `ex`; two units of one group with the same `roman` and no `confuse` link; a sounded unit with no `say` while `tts` is on; an `alt` equal to another same-stage unit's `roman` (typed answers would accept the unit as that letter's sound), except between units of the same glyph or units that accept each other's roman.

## lessons.json

Optional. The shape is unchanged from hsk's `LESSONS`.

```
[{ id, title, blurb,
   cards: [{ h, body, rows?: [[col1, col2, col3]], say?: [string] }],
   items: [{ t: "mc", q, say?, opts: [string], a, rv? }] }]
```

**Unlocking.** A level's passages unlock once 70% of that level's words are learned (core.js `READ_UNLOCK`, `readingLevels`). The unlock is stored in `prog.read.unlocked` and stays even if the count later drops. A locked level shows the threshold and the learned count.

**Today.** Passage reading is the last Today stage, after Sentences (core.js `nextReadItem`, app.html `todayStep` step 5). It runs one passage per session: the first not-done passage at an unlocked level, in pack order (`suggestPassage`, reason `new`). When every unlocked passage is done, it offers a re-read (reason `reread`). The candidates are passages whose latest attempt missed a question (`done[id].sc < n`). The one completed longest ago is chosen, and only once at least 7 days have passed (`READ_REREAD_DAYS`). Ties go by pack order. With `rereadPerfectDays` (zh: 30), a done passage with every question right (`sc >= n`) is also a candidate once its latest attempt is at least that many days old; it is chosen only when no missed passage is due, oldest first (owner 2026-10-03: a passage got right should still come back, later). Exception, same flag: a perfect passage whose record has `x` 1 and no `l` (read once, never listened to) is a candidate after `READ_REREAD_DAYS` (7), ranked with the missed ones (oldest `d` first among all 7-day candidates), and `readPassMode` makes it a listening pass (owner 2026-10-03: a good reading score says little about listening). A perfect passage with `x` >= 2 or `l` follows the 30-day rule. No stored field is added. On a device that cannot listen, that 7-day return runs as a reading pass (`readPassMode` unchanged), which is acceptable. Same reason `reread`, so the listening-pass alternation, results and `done` record are unchanged, and a paused pack (`pauseNew`) still offers it. Absent, only missed passages return. With no candidate the stage is absent: no plan row, and the session ends after Sentences. The plan lists it as `Read | 1 passage: <title> (<level>, N words)`, or `1 passage to re-read: ...`, or `Listen | 1 passage to listen to: ...` for a listening pass. The title renders as target-language text (reading-first under `pronFirst`), and the rest goes through `ui()`. The stage uses the Read tab's screens. Only two things differ: "Skip today" replaces the passage-list link, and the results end with Continue instead of "Add to review" / "Back to passages". Continue applies the ticked weak words (all by default) as "Add to review" does, then finishes the session. The passage is recorded in `prog.read.done` exactly as a Read-tab completion is. "Skip today" records nothing, so the passage is not done and comes back next session. The session still counts as usual. The Read tab stays for free reading. **Rotation** (`readRotation`, zh; owner 2026-10-03: "say I finish 60 passages in 60 sessions in a day", day gates say little; "why not choose randomly from already read stories and also random question order?"): no day gate and no `rereadPerfectDays`. `sn` is the session being planned: the Today home plan is made before Go starts the session, so it is `prog.sn` + 1 (dayAware); a replan inside a started session (app.html step 5, e.g. a planned first read dropped after pausing) uses `prog.sn`. So the home plan excludes nothing (no pass can carry the not-yet-started session's number): the previous session's passage and a Read-tab read between sessions may be the next Today pick. Only an in-session replan excludes the passes of that session (`s === sn`, a Read-tab pass before the stage). Turn: when the latest pass (highest `s` among records) was a reading pass (no record has `ls` equal to it), it is a listening turn; otherwise, or with no record carrying `s` (nothing passed under the flag), a reading turn. Listening turn (only passages this device can hear, `canListenPassage`): random among done passages at unlocked levels not passed in the session being planned, never-listened (`ls` absent) first, then the smallest `ls`, ties random; reason `reread`, `mode: "listen"`. Nothing eligible (no passage read yet, or no voice) falls through to the reading turn. Reading turn: the first not-done passage (reason `new`), else a re-read: random among the same candidates, missed (`sc < n`) first, fewest `x`, ties random. Paused (`pauseNew`): the same without new passages. So from scratch: new, listen (the passage just read), new, listen (the new one, never listened), ... `readPassMode` returns the item's `mode`. Picks use `rng` when given (tests), else a generator seeded by `sn` and the total pass count, so the plan does not change on a re-render; Go stores the item (`todayStepState.read`) and a resume keeps it. Every pass, Read tab included, asks the questions in an order shuffled by a seed from the passage id and the attempt count `x` (core.js `passageForPass`; `RD.qx` keeps the seed, so a resume of the results screen after the record moved on keeps the order); answers, weak words, the results lines and "question shown" go by position in that order, i.e. by question. `markPassageDone(prog, pid, sc, n, d, listen, pack)` writes `s` = `prog.sn` and, on a listening pass, `ls` = `prog.sn` (a reading pass keeps the previous `ls` and, under this flag, the `l` a listening pass earned: `l` is credit in the goal position, and alternation reads the item's `mode`; without the flag `l` marks the latest pass and `readPassMode` alternates on it, so a reading pass still replaces the record). **Re-entry.** A Read-tab passage survives a tab switch: returning to the tab resumes it on the same screen. A tab switch ends the Today stage with the rest of the session. Returning to a passage screen, or a late voice list re-mounting it, restores the screen and speaks nothing again: option order, shown translation or question, the passage toggle, an answered question's reveal (no replay of the source sentence), and on results the unticked weak words and a done "Add to review" (it cannot apply twice). A question first mounted without a voice is spoken when a voice arrives, once, only while unanswered. Other screens with state a re-render would lose are left alone on a voice change: a drill item, a Today teach screen between steps, and a placement run or its result. Packs without passages render Today byte-identically to before.

**Flow.** Reading screen: sentence by sentence, tap-to-gloss on linked words (each tapped id is logged), optional per-sentence read-aloud when speech works or the sentence has `audio`. "Done reading" starts the questions, one at a time, with the passage hidden behind a "Show passage" toggle. Opening it before answering is logged for that question. Each question is spoken (TTS only, questions carry no `audio` field) with a Replay button when speech works; its English translation (`questions[].en`), when present, stays behind a "Show translation" tap rather than showing by default; a peek before answering is noted (" · translation shown") on that question's results line, but unlike reopening the passage, it does not feed `passageWeakWords`. The verdict ("Right." / "Not quite.") and its source sentence sit under the options, above the "Show passage"/"Hide passage" toggle; answering with the passage open brings the verdict into view instead of scrolling to Next below the passage, and with `readAnswerBlock` Next moves up under the verdict too (owner feedback 2026-10-02). Feedback highlights the source sentence and plays its clip or TTS (also Replay-able), cancelling the question's own speech first, with a Replay per source sentence again on the results screen (no autoplay there).

**Listening pass.** A Today re-read (reason `reread`) runs as a listening pass when this device can hear every sentence of the passage (each has `audio`, or a TTS voice is usable: app.html `canListenPassage`, per device) and the latest attempt was not itself a listening pass (`done[id].l`), so re-reads alternate listen, read, listen (core.js `readPassMode`). Otherwise, and for every first pass and Read-tab passage, it is the reading pass above. The voice is re-checked when the stage starts. The listening screen shows a numbered play row per sentence instead of its text (clip, else TTS), "Play all" (the sentences in order, each after the previous one ends; Stop, a row tap, or leaving the screen, a tab switch included, stops it and the current sentence at once) and a "Show text" toggle that shows the ordinary passage rows with tap-to-gloss; using it is logged (`peekText`). "Done listening" starts the questions. While a voice is usable, ceil(n/2) of the questions are audio-only: spoken on mount as usual, with the question text and its "Show translation" behind a "Show question" tap, which is logged for that question when used before answering; answering reveals it too, unlogged. With pack `listenQuestions: "all"` (zh; owner 2026-10-03) every question is audio-only: `listenAudioOnly(pid, attempts, n, pack)` returns 0..n-1, and the "Show question" tap, its `peek` logging, reveal on answering and the results lines are unchanged. Without it the pick is core.js `listenAudioOnly`: a question order shuffled by a seed from the passage id, rotated by the previous attempt count `x`, first ceil(n/2) taken, so with two or more questions consecutive re-reads never hide the same set. It also changes the per-question look-back of a listening pass (owner 2026-10-03: "if I click show passage I see characters again, why?"): the toggle reads "Replay passage" (then "Hide passage") and opens the play-row list of the listening screen (numbered rows, each plays its clip/TTS, "Play all"/Stop, no text) instead of the written passage; opening it before answering is not tracked (owner 2026-10-03: no `reopened` flag, no effect on weak words or the results). A "Show text" toggle inside the list shows the written rows with tap-to-gloss and is a plain toggle that logs nothing (no `peekText`). Closing the list, answering to the next question or leaving the screen stops audio; the open list and its text state (`rd.shown`, `rd.qv[i].lkText`) are saved for session resume. Reading passes are unchanged. With clips and no voice no question is audio-only, since questions have no clips. Options, feedback and weak words are unchanged, and so is "Show passage" in reading passes (in a listening pass with `listenQuestions: "all"` it is "Replay passage": play rows, Show text logs `peekText`). Results add a "Listening pass" line and ` · question shown` on each question whose text was revealed before answering. The attempt is recorded with `l: 1`.

**Weak words.** The results screen lists the union of tapped words and the `words` of wrongly answered questions (`passageWeakWords`). Each has a checkbox, ticked by default. Looking back at the passage is not tracked for any pack (owner 2026-10-03, superseding the 2026-09-28 weight-0 label): no `reopened`/`peekText` flag, no marker on the results, no effect on weak words; a stale `reopened` flag in an older session record is ignored. A wrong answer is a miss either way. When no word is listed, the list, its heading and "Add to review" are not shown. "Add to review" adds misses to `prog.w[id].w`: 2 for tapped or wrong, the largest reason winning (`READ_WEIGHT`, `applyWeakWords`). The streak resets as for any miss, so `weakScore` ranks them first in the next review. A word not yet learned is flagged `d` (drilled ahead), which puts it in the review pool. As with a Words-tab drill-ahead, a `d` word then counts as learned everywhere, including the 70% unlock threshold. This is intended. The passage is recorded as done in `prog.read.done[id] = {sc, n, d, x, l?}`: latest score, question count, date, attempt count, and `l: 1` when that latest attempt was a listening pass (absent for a reading pass).

**Progress.** `prog.read` (`{unlocked: {levelId: 1}, done: {passageId: {sc, n, d, x, l?, s?, ls?}}}`) is created on first use, exported and imported with the rest, and checked by `validateProgShape` (`l`, `s`, `ls`, like `sc`/`n`/`x`, must be numbers when present). Stored progress without it loads unchanged, and so do `done` records from before listening passes (no `l`) and from before `readRotation` (no `s`/`ls`: under rotation such a record is never-listened and not passed in the latest session). `s`/`ls` (fb16) are written only under `readRotation`; an older engine keeps them on boot and drops them from a record it re-marks (migration_checks [rotation-s]). The Progress tab shows passages done and the average latest score per level.

**Script display.** Titles, passage sentences, questions, mc options and gloss words carry `lang`, `dir="rtl"` and the pack fonts, as everywhere else. English translations and True/False labels do not. In RTL packs the tap-to-gloss popover itself is `dir="rtl"` with `text-align:start`, so the tapped word sits at the right edge and its `pron` and English gloss follow in reading order. Those two stay isolated left-to-right runs (`dir="ltr"`).

## patterns.json

Only with `pack.patterns` (see "patterns"). A list in level order:

```json
{ "id": "p06", "lv": "3", "label": "虽然…但是", "en": "although … (but)",
  "note": ["Admits one fact, then turns against it.", "虽然 A，但是 B"],
  "near": ["p20"], "keys": [12, 40],
  "sentences": [{ "id": "p06.1", "t": "…", "en": "…", "lv": "3", "words": [12, 40], "pron": "…", "marks": [[0, 2], [5, 7]], "ruby": [] }] }
```

`id` unique; `lv` a pack level, non-decreasing through the file; `label`, `en` non-empty; `note` 1–2 non-empty lines of at most 60 characters; `near` (optional) other pattern ids whose mark words could also fit a blank, never offered as wrong choices; `keys` (optional, written by pack_from_hsk.py: the sentence word ids whose text is a mark text) a list of word ids that occur in the pattern's sentence `words`, all learned before the pattern opens; `sentences` non-empty with ids unique across the file (validator checks the whole file), `t`, `en`, `pron` non-empty, `lv` equal to the pattern's, `words` known ids none above the pattern's level, `marks` a non-empty sorted, non-overlapping list of UTF-16 `[start, end)` ranges inside `t` covering non-blank text and never splitting a `ruby` token, `ruby` as sentences.json. Validator: `pack.patterns` must be a bool and needs `pairs`; `patterns.json` missing with the flag on is an error, present with it off a warning.

## legacy.json

Optional, required when `pack.legacy` is set (and must be absent otherwise). Maps an old standalone app's own ids to this pack's ids, for a one-time progress migration (`docs/HSK_MERGE.md` §4) that this schema and its tooling only carry the data for; the migration function itself lives in `engine/core.js`.

```json
{ "w": {"你好": "w0028"}, "s": {"你好，我是学生。": "s0001"}, "c": {"你": "c0001"} }
```

An object with up to three optional keys, each a map from an old-app string key to an id in this pack:

| key | maps to | meaning |
|---|---|---|
| `w` | `wordId` | Old word key (e.g. the hanzi surface) to this pack's `words.json` id. |
| `s` | `sentId` | Old sentence key (e.g. the sentence text) to this pack's `sentences.json` id. |
| `c` | `unitId` | Old character key to this pack's `characters.json` id. Only meaningful with `pack.characters`. |

`tools/validate_pack.py` checks that every mapped id exists (in `words.json`, `sentences.json`, or `characters.json` respectively) and warns if a map's values are not unique.

## Session resume

Not a pack field: every pack gets it (app.html "session resume", core.js `sessionKey`, `sessionHash`, `sessionStale`; tests/session_resume_checks.js). A drill or passage in progress survives an app-tab switch and a page reload.

- **What resumes**: Today (Review, Learn drill, Listen, Recall, Sentences, the Read stage, the stage between drills, a Learn teach screen), Test drills, the Words-tab set drill and review, Sounds lesson and script drills, and the Read passage flow (passage screen, each question, results). Placement does not. The item on screen comes back with the same options in the same order; the queue keeps its order, kinds and labels; right/seen counts and the missed list are kept; a typed item missed twice comes back as its choice counterpart. A results screen comes back with its Continue, and Today then goes on to the next stage.
- **Tabs**: each app tab keeps its own session, so a Test or Words drill or a passage started while a Today session is under way never drops it. Leaving a tab keeps its session; returning to it resumes. Tapping the tab already open, Escape in a drill and "‹ passages" leave to the tab's home screen and keep the session: that screen offers "Resume drill" / "Resume passage" at the top, and Today's Start button reads "Resume today" and resumes. Starting another drill in the same tab replaces that tab's session. A finished session (results Continue, "Back to passages", the end of Today, or a re-tap of the tab while a Test/Words/Sounds drill's or a Read-tab passage's results show) is dropped; a Today drill's results are mid-session and stay. Placement does not resume.
- **Boot** restores exactly what was on screen when the page went away: the session that was showing (same item), else the home of the tab that was showing. A session the learner left (tab switch, re-tap, Escape, ‹ passages) is never opened at boot; it comes back through its tab, its Resume button or "Resume today".
- **Storage**: one JSON value under `vocab_<key>_session` in localStorage, else in memory for the page's life. It survives a reload, an app switch, a tab the phone discarded, a closed and reopened tab and a home-screen relaunch (sessionStorage, used before 2026-10-02, is empty in a new browsing context, so those restarted). The value is the latest record with the other app tabs' records under `park: { <tab>: record }` and `view: { tab, live }` (the tab on screen at the last change; `live` when its session was showing). Two open tabs of one site share it: the second opens on the first one's item, and the last writer wins. Each record is `{ v, build, t, fp, tab, today?, drill? | rd? }`: `drill` holds each queued item as its builder name and arguments (words, sentences, units and lesson items by id or index) plus, for the item on screen and items already shown, its builder's random draws, replayed on rebuild: a core.js call that drew is kept as its result (`{ m, r }`, e.g. the three distractor ids of `meaningOpts`), other draws as numbers; the missed list holds each missed item's recipe once per key (its reveal is rebuilt); a Today script-Learn results screen names itself (`sm`) so "One more set" survives. A 40-answer Test drill with every item missed once stays under ~6 KB (zh, es); `rd` is the passage state with the passage by id; `today` holds the stage index and the Read-stage pick. Saved on every item shown and every answer, on a tab switch and on page hide.
- **Voices after boot**: a hear item rebuilt while the pack's language has no listed voice comes back as a read item with the no-voice notice; when a voice arrives (voiceschanged), every such item not yet answered is rebuilt as a hear item with the same options, and the one on screen is shown again, playing.
- **Question order** (`readRotation` only): `rd.qx`, the attempt count that seeded the passage's shuffled question order, so a resume (also of the results screen, after `x` moved on) asks in the same order. A record without it resumes in pack order. Not a progress field.
- **Characters set** (`characters.learn: "lag"` only): `today.cu`, the unit ids of the Learn step's characters set, so the resumed step teaches the same units (sets are dynamic there).
- **Words asked typed** (`wordsBy: "typed"` only): `today.tw`, the word ids asked typed this Today session, so a resumed session does not ask them typed again; `drill.dn`, the word ids a miss in the drill stepped down from 2+, so their retry after a reload still gets no streak credit (see "wordsBy").
- **Progress is never in it**: answers are written per answer to `vocab_<key>` exactly as before, so a dropped record loses nothing recorded. No progress field is added or changed.
- **pauseNew**: a resumed Today session reads the pause at its Learn and Read steps (see "pauseNew").
- **Dropped silently** (`sessionStale`): a record from another build (the build id build.sh writes into app.html's `VE_BUILD`, a cksum of engine + pack sources, known while the page still parses; dev mode uses `dev`; plus a pack fingerprint), saved more than 12 h ago (or over a minute in the future), or, at boot, whose progress fingerprint no longer matches the stored progress (the raw stored string or its normalized form; something other than this engine changed it). The fingerprint is `sessionHash` of the progress as last stored: every progress save by the page (answers, Read unlocks, settings) re-fingerprints all its records, so the page's own writes never invalidate a parked session. Import and "Reset all progress" drop every record. An unreadable record or one that no longer rebuilds is dropped the same way.

## Validation

`python3 tools/validate_pack.py <packdir>` checks the following. Exit status 1 means at least one error.

- Required fields and types for every file.
- Unique ids.
- Every `lv` is a pack level.
- Every level has at least one word. A level with fewer words than `setSize` produces a warning.
- Every `sentence.words` and `functionWords` id exists.
- `placement` levels exist, are in order, and fit the level's set count.
- Every placement bucket has at least 3 words. This is computed with the same set-boundary math as core.js `strata()`, and a test asserts parity via `--dump-strata`.
- `typing.strictFromLevel` exists. `typing` is an object, `"pron"` or `null`; with `"pron"`, no word having a `pron` is an error and some words lacking one is a warning.
- `tones`, when present, is `"pinyin"`. `soundsReference`, when present, is `true`; a warning when `hasLessons` is not true or no lesson row has a one-character `say`.
- Script fields: `rtl` is a bool, `langTag` is a BCP-47 tag, `fontFamily` has no `;`, `{`, `}`, `<`, `>`, `\`, `/*` or `url(`, every `fonts` entry is a Google Fonts family name, and `lineHeight` is 1–4. A pack with `rtl` true and neither `fontFamily` nor `fonts` gets a warning.
- Lesson answers are among their options.
- `passages.json`, when present: unique ids, `lv` is a pack level, `title`/`text` non-empty, non-empty `sentences` with `t`, `en` and known `words` ids, optional `spans` (a list of `[start, end, wordId]`, or `[start, end, wordId, gloss]` with a non-empty gloss string, with integer UTF-16 offsets, `0 <= start < end <= len(t)`, sorted, non-overlapping, not splitting a surrogate pair, `wordId` in that sentence's `words`, covering non-blank text), non-empty `questions` with `q`, `type` mc or tf, mc `options` of 4 distinct strings with `answer` 0–3, tf `answer` a bool and no options, known `words` ids, and `sentence` a valid index. A sentence `t` missing from `text` and a question with empty `words` are warnings.
- `pack.characters`, when present: `stages` is a non-empty list of `{after, levels}` with existing level ids, `after` non-decreasing in `pack.levels` order, and every level id covered by exactly one stage; `mastered`/`setSize` positive ints and `bare > mastered`; `learnKinds`/`reviewKinds` non-empty lists of known kinds; `testKinds`, when present, a non-empty object of known kinds to positive weights; every `stages[].levels` id at or before that stage's `after` in `pack.levels` order. `characters.json` must exist exactly when `pack.characters` does, each error naming which side is missing.
- `characters.json`, when present: unique ids, non-empty `t`, non-empty `words` with known word ids, and `lv` a pack level, equal to the level of `words[0]`, and covered by a `pack.characters.stages[].levels`. `say`, when present, is a non-empty string other than `t`; a warning when it differs from the `say` of a `words[0]` with the same text (that word's is the one spoken).
- `words[].say`, when present: a non-empty string other than `w`.
- `sentences[].spans`, when present: the `passages.json` `spans` rules without the `gloss` element (a 4-element span is an error). A linked word with no valid span in a sentence that has spans is counted into one pack-level warning (the builder's coverage metric); the summary line gains `N sentences with spans` only when some sentence has them.
- `sentences[].ruby` (and `passages.json` `sentences[].ruby`), when present: same offset rules as `passages.json` `spans` (sorted, non-overlapping, in-bounds, no split surrogate pairs, non-blank), plus a non-empty `reading` and a `wordId` that is either `null` or both in the sentence's `words` and some `characters.json` unit's `words[0]`.
- `passages.json` `titleRuby`, `questions[].ruby` and `questions[].optionsRuby` (one ruby list per option, same length as `options`), when present: the same offset and reading rules against `title`, `q` and each option, with `wordId` `null` or some `characters.json` unit's `words[0]`. Without `pack.characters` they are a warning.
- `pack.script` and `script.json`, when present: see "Script primer" above.
- Recorded audio: `pack.audio`, when present, is `{voice, version}` with a non-empty `voice` and an integer `version` ≥ 1 (other keys are a warning). `audio` on words, sentences and passage sentences is a non-empty string when present. `pack.audio` with no clip anywhere (words, sentences, passage sentences or script units), relative clips without `pack.audio`, and relative clips with no file beside the site page (resolved against the pack directory's parent, where a language repo's `index.html` sits) are warnings. `packbuilder audio --check` checks that the files exist (docs/AUDIO.md).
- `pack.legacy` and `legacy.json` must exist together, and every value in `legacy.json`'s `w`/`s`/`c` maps is a real `words.json`/`sentences.json`/`characters.json` id (duplicate values across one map are a warning).
- The generated `.js` files are in sync.

A word that shares its surface form with another word at the same level produces a warning.
